# Vega netspec contract — the spec, its provenance, the compiler, the `architecture` layer

`/vega-forge` turns the decisions the chain already took — the blueprint's model-family posture, the shaper's feature contract, the geometry's partition, the analysis's findings — into a **network specification**: one declarative JSON, `netspec.json`, that names every architectural, objective, optimisation and regularisation choice **with the source that justifies it**. The spec is the truth of the whole network sub-chain: the backend compiles exactly it, `/vega-train` runs exactly it (and every experiment is a *delta* on it), `/vega-pack` ships it, and the layer shows it. Nothing about the network exists outside the spec.

**The input digests.** `input.manifest_digest` is the shape layer's `manifest_digest` copied as it stands (the sha256 of the shaped `manifest.json` **file**, which `/dataset-shaper` records and `pipeline.json.input.shape_manifest_digest` repeats). `input.pipeline_digest` is the **canonical digest** of the blueprint's `pipeline.json` — the sha256 of the parsed document re-serialised with sorted keys and no whitespace, `"sha256:" + sha256(json.dumps(doc, sort_keys=True, separators=(",", ":")).encode("utf-8"))`, not of the file's bytes — the same digest the emitter stamps into `blueprint-map.json.pipeline_digest`, so the spec, the map and the bundle name one blueprint by one number. `compile_spec.py` recomputes it from the `pipeline.json` it compiles against and refuses a spec whose `pipeline_digest` is missing or differs (D1e, printing the digest it computed), and refuses a manifest digest that differs between the blueprint, the spec and the shape layer (D1b).

Every **choice** — `family`, each block, `loss`, `metrics`, `optimizer`, `schedule`, each `regularization` entry, `early_stopping`, `init`, `training` — carries `source`, `rationale`, and `alternatives` (the ones actually weighed, each with a `when`). `alternatives` may be empty only for a **structural** choice — one the catalog marks as forced by another choice (`concat` after an `embedding`, the head's `out` under the task) — and then `rationale` says what forces it. A block nested in the `inner` of a `residual`, `sequential` or `parallel` inherits its parent's provenance: the inner blocks are the composition the parent's choice names — its family's composition in `family-catalog.md` §2 (`mlp-residual`'s `residual(inner: dense → batchnorm|layernorm → activation → dropout)`, the norm and the activation the row's *defaults* column names — `batchnorm` at batch ≥ 32, `gelu`) or the finding the parent cites — so the parent's `source`, `rationale` and `alternatives` cover them. A nested block that departs from that composition (another normalisation or activation, a block the composition does not name) is a choice of its own and carries its own `source`, `rationale` and `alternatives`, so it is surfaced like any choice and, when it is a `vega:default`, enters `defaults_to_test`. A `vega:default` source also carries `catalog: "<section>/<row>"` naming the catalog row it cites (`defaults/optimizer`, `blocks/concat`, `families/mlp-residual`) — a list when one choice bundles several rows (`training` cites `defaults/batch_size`, `defaults/max_epochs`, `defaults/device`, `defaults/precision`, and a `defaults_to_test` entry may then name a sub-path such as `training/max_epochs`); `seed` is the chain's and cites `defaults/seed` implicitly; the compiler resolves it against `scripts/catalog.json`, the catalog's machine copy (`family-catalog.md` says what it holds) that the build keeps in sync with the prose (a test fails when they differ). The compiler refuses a choice without `source`, a `source` that does not resolve, a `vega:default` without a catalog row, and a non-structural choice with empty `alternatives`.

**Sources** (the closed set; the compiler resolves each against the input file, the shaped directory and the blueprint run):

| source | resolves to |
|---|---|
| `blueprint:posture` | `pipeline.json` → `posture` (the model-family bet, resolved or auto-resolved) |
| `blueprint:bets/<id>` · `blueprint:<key>` · `blueprint:ports/<name>` · `blueprint:modules/<name>` · `blueprint:boundaries/<name>` · `blueprint:artifacts` | an entry of `pipeline.json.bets[]` (the resolved structural bets, by id), a top-level key (`serving`, `training`, `monitoring`, `feature_contract`), or an entry of the world model in machine form (`ports[]`, `modules[]`, `boundaries[]`, `artifacts[]` — `code-contract.md` §1). The blueprint is **required**: a spec without `input.pipeline` is refused |
| `shape:manifest/<key>` · `shape:S<n>` | a key of `shaped/manifest.json` — `output_schema`, `outputs/files`, `label`, `steps/S<n>` (each step record carries `fit_on` and `parameters_fitted`; an `encode` step's `parameters_fitted.unseen_category_id`) — or a recipe step |
| `geometry:partitions/<label>` · `geometry:partitions/chosen` · `geometry:typing/<col>` · `geometry:space` | the geometry layer's keys **resolved as `/dataset-shaper` resolves them**, not dug literally: the geometry layer's `partitions` (its shape is `report-contract.md` §1's) holds a chosen candidate and candidates by label, so `partitions/<label>` is the candidate whose `label` is `<label>` (as `shape.py`'s source resolver reads it) and `partitions/chosen` is the chosen one; a resolver that indexes `partitions[<label>]` finds nothing and is the defect this row names |
| `analysis:F<n>` · `analysis:modules/<name>` · `analysis:context.time` · `analysis:context.spatial` | a finding, a module (`analysis:importance` is accepted as an alias of `analysis:modules/importance`), or the context of the analysis layer |
| `user:<turn>` · `user:stance/<line>` | something the user said in this run, or a recorded **Network stance** — the one source no file can resolve: the compiler checks its form only, so it is never written without the user's own words in this conversation or the memory line that recorded them, and the choice's `rationale` quotes them (an unattended run has no conversation turn: its only `user:` sources are the flags the user typed on the invocation — `--family <name>`, `--goal`, a given `--spec` — each a `user:` source whose rationale quotes the flag as typed; `--family` settles `family` and `--goal` the task, while a given `--spec` stamps nothing: its choices keep the sources written in it, and a choice in it is `user:` only when the file itself says so) |
| `vega:default` | a choice the skill made because the family catalog names it as the default for this family and task — always with `rationale` and a `catalog` row, and ≥ 1 alternative unless the row marks the choice structural |

A reference to the test part anywhere in the spec (`data_contract.parts.test` other than `"sealed"`, a metric monitored on `test.*`) is refused: the test part belongs to `/vega-eval`, which reads its path and digest from the manifest (`outputs.files.test`) when it opens it — `/vega-forge` and `/vega-train` check that part by *name* only and never hash or open it.

**Task vocabulary.** The geometry's candidate carries `task` as prose (`"binary classification"`, `"multiclass classification"`, `"regression"`, `"none"`); the catalog's §1 maps it to `task.kind` (`binary`, `multiclass`, `multilabel`, `regression`, `ordinal`; `none` → `unsupervised`, or `anomaly` under `--goal anomaly`; the `sequence-*` / `forecast` kinds when the time context, the split and the windows say so), and `--goal reconstruct` on a labelled dataset is `unsupervised` with the label ignored — the mapping is a compiler table (`scripts/catalog.json`), not a judgement.

**Task fields.** Beside `kind`, `label`, `classes`, `positive` and `source`, the task carries what its readers need to agree on the task's meaning (machine copy: `catalog.json` `task_fields`):

```json
"task": { "kind": "sequence-classification", "base_kind": "multilabel", "label": "tags", "classes": ["a", "b", "c"],
          "label_format": { "kind": "delimited", "sep": "|" }, "positive": null, "source": "geometry:partitions/chosen" }
```

`base_kind` (`binary` | `multiclass` | `multilabel` | `regression` | `ordinal`, a key `catalog.json` `sequence_map` sends to `kind`) is required iff `kind` starts with `sequence-`, and every reader of the base — head, loss, metrics, readout, the serving reading — reads it; the shapes of the head or the loss are never used to guess it. `classes` is required for `binary`, `multiclass`, `multilabel` and `ordinal` (in order for `ordinal`). A `multilabel` label is **one** shaped column holding a delimited set of class names (`"a|c"`, the empty string for the empty set), so `label_format` (`index` | `names` | `delimited`, with `sep`) is required there; elsewhere it defaults to `names` when the column holds strings, else `index`. `positive` names the class that means positive (`binary`, and a `sequence-*` kind whose base is `binary`) or anomalous (an `anomaly` task with a label). For a binary task it **must be the second class**, `classes[1]`: the logit, the threshold and every reader take `classes[1]` as positive, so T1e refuses a spec that names `classes[0]` ("list the positive class second") rather than read it the other way round; unstated, it is `classes[1]`. `anomaly_rate` (optional; an `anomaly` task only) is the expected share of anomalous rows, a number in `(0, 1)` with its own `anomaly_rate_source` from the closed set (`user:<turn>` or `analysis:<path>`): `/vega-eval` reads it for an unlabelled anomaly task — `precision_at_k`'s `k` and the threshold's valid quantile (`eval-contract.md` §3) — and without it that task's threshold does not apply (the reading answers the score). A labelled anomaly task takes the rate from the train part's positive share instead, and ignores the field. Binary and multilabel scores are logits everywhere in the sub-chain, and the sigmoid is applied unconditionally by every reader.

**Sample shapes** (`data_contract.sample`, v2.3). `data_contract.sample.shape` is one of three, each fully specified:

```json
"sample": { "shape": "row" }

"sample": { "shape": "window",
  "length": 24,                         // L >= 2: the anchor row and the L-1 rows before it in its series
  "stride": 1,                          // training anchors are thinned by it; scoring is always dense (stride 1)
  "horizon": 3,                         // forecast only: H >= 1 steps ahead; absent otherwise
  "series_by": "station" | null,        // a key column: windows never cross it
  "order_by": "ts" | null,              // a key column: the order within a series; null = the part's stored order
  "context": "previous-part" | "none",  // defaults/window_context
  "autoregressive": true | false,       // forecast only; defaults/autoregressive
  "season": 24 | null,                  // mase's seasonal scale and the seasonal-naive baseline
  "source": "analysis:context.time", "context_source": "…", "autoregressive_source": "…", "series_source": "…" }

"sample": { "shape": "graph",
  "edges": "<manifest.outputs.files.edges path>",
  "level": "node" | "graph",
  "graph_id": null | "<column>",        // a key column; required iff level == graph
  "directed": false, "self_loops": false,   // copied from shape:manifest/graph
  "protocol": "inductive" | "transductive", // defaults/graph_protocol
  "batching": "full" | "sampled" | "graphs", // defaults/graph_batching; graphs iff level == graph
  "neighbours": null | [25, 10],        // required iff batching == sampled: one fan-out per conv block
  "exposure": null | { "kind": "features", "rows": "test", "source": "user:<turn>" },  // required iff transductive
  "source": "shape:manifest/graph" }
```

`data_contract.keys` is derived: the non-null key columns among `series_by`, `order_by` and `graph_id`. A key column must be in `shape:manifest/output_schema` and is **not a feature**: `input_dim` counts the output schema minus the label minus the keys.

**Windows.** Each scorable row is the **anchor** of one window: the anchor and the `length − 1` rows before it in the same series (`series_by`), in `order_by` order. With `context: previous-part` (the default) the context rows of a part's first anchors come from the tail of the previous part of the same series — train before valid, valid before test — so every valid and test row is scored; with `context: none` the first `length − 1` rows of each series in each part are not anchors and are counted unscored. Training anchors are thinned by `stride`; scoring (valid, the sealed test, serving) is dense, one prediction per scorable row, and a prediction's `row_id` is the raw position of its anchor. A `sequence-*` target is the anchor row's own label; a `forecast` target is the label of rows anchor+1 … anchor+H of the same part and series, and an anchor whose horizon runs past its part is unscored. Nominal columns keep their step axis: `x_cat` is `(B, L, C)`. **Autoregressive** (`forecast` only; `true` by default): the target's rows up to and including the anchor are one more input channel, appended to the numeric stream (`F′ = F + 1`); the bundle's schema then lists the target column as an input with `"role": "autoregressive"`, required in a request's `rows` and `history`. `autoregressive: true` on any other task is refused: there the channel would carry the anchor's own label.

**Graphs.** Rows are nodes and carry the row's features; the `edges` part comes from the shaper's `graph_edges` step (`manifest.outputs.files.edges`; its schema is `dataset-shaper/references/shape-contract.md` §2's — raw-file positions with each end's part — and the data adapter resolves them to part rows through the shaper's `__split_raw__`) and the `source` is the manifest's `graph` block, which records the step's method (key pair, kNN, spatial neighbours) as a shaping stance. `level: node` is the default: the label is the partition's label on each row, and the task rows of `family-catalog.md` §1 apply unchanged. `level: graph` groups the rows by `graph_id` into graphs with one label per graph (a label that is not constant within a graph is refused, naming it); it requires the shaper to have written `graph_id` in the manifest's `graph` block and a `graph_pool` block before the head.

**Protocol.** `inductive` (the default — `vega:default`, `catalog: defaults/graph_protocol`) keeps the test seal's meaning, and one rule decides every view — training, evaluation and serving alike. **Reference** nodes have their representations computed over the reference graph (every edge whose two ends are reference nodes); **query** nodes receive messages from reference nodes only — there is no query → reference and no query ↔ query edge, so an answer never depends on the other rows of a request. The training valid view has the train nodes as reference and the valid nodes as queries; the sealed test view at `/vega-eval` has train ∪ valid as reference and the test nodes as queries; a served request's nodes are queries against the bundle's reference graph (train ∪ valid). At `level: graph` a query is a whole graph, and its within-graph edges are all kept. `transductive` puts the test nodes' *features* and their edges in the graph during training while their labels stay sealed — allowed only with a `user:` source, and recorded in the layer as a disclosed exposure of features (`exposure: { "kind": "features", "rows": "test", "source": "user:<turn>" }`); it is evaluated but not packed (`/vega-pack` refuses it). This is the one exposure of the test part any stage before `/vega-eval` may have, and it is the user's, never a default: the seal protects the test **labels** and the evaluation's one look, and under every `inductive` graph spec and every row or window spec no stage before `/vega-eval` opens the test file at all (the forge and the trainer name it only as `"sealed"`; the smoke record's `test_edges_withheld` counts rows of the **edges** part whose end is a test node, without opening the test part). The door is named: the data adapter's `open_features_only` reads the test part's **feature columns alone** (never the label) and only for a graph spec whose protocol is `transductive` with `sample.exposure` declared by a `user:` source — any other caller gets `SealedPartError`; the forge's smoke pass builds the training view through that door (the transductive graph *is* the training graph), `/vega-train` trains on it, and the test labels are still read only by `load_sealed_part` with `/vega-eval`'s token.

**Batching.** `full` (one batch is the whole view; `training.batch_size: "full"`, and only then), `sampled` (neighbour sampling for training, `neighbours: [k1, k2, …]` one fan-out per conv block, drawn with replacement; `training.batch_size` counts seed nodes), or `graphs` (mini-batches of whole graphs at `level: graph`; `training.batch_size` counts graphs). Scoring is always full-batch over the view; a view larger than memory is an `ERROR:` that names `sample.batching`.

## 2. The block grammar

Blocks are typed nodes with `params` and an `id` unique in the spec, matching `^[A-Za-z0-9_.@:-]{1,128}$` (the id names the block everywhere downstream — the smoke record's `per_block`, the history's per-block norms, the inspection stage graph's node and tensor ids, which refuse any other id — so the grammar is one; nested blocks take the composer's dotted ids such as `B3.1`); the backend maps each type to framework code, and the grammar is open at two ends — a composite block (`sequential`, `residual`, `parallel`) nests any blocks, and a `custom` block carries code. The types the shipped backend understands are enumerated in `family-catalog.md` § Blocks (dense, embedding, concat, batchnorm, layernorm, dropout, activation, residual, sequential, parallel, conv1d, pool1d, rnn, gru, lstm, attention, attention_pool, transformer_encoder, feature_tokenizer, positional, flatten, reshape, pool, head, decoder, reparameterize, gcn_conv, sage_conv, gat_conv, gin_conv, graph_pool, edge_dropout, custom) with their params and shape rules; `scripts/catalog.json` is the machine copy the compiler reads. A type the catalog names but the backend's `coverage.json` does not list under `blocks` is known to the grammar and refused by the backend check, B2 — as *planned in that backend* when its `planned.blocks` carries it, as *not covered* otherwise — a different refusal from an unknown type, and the message says which. A type outside that list is refused with the nearest known type named; a family outside the catalog is accepted when its blocks are known (the catalog says so: families are named compositions, not a closed set).

`custom` blocks carry `params.code_ref` (a file under the **campaign root**, `custom/<id>.py`, exposing `build(in_shape, params) -> module` — resolved against the campaign root, never against a run's own directory, so a rung that re-emits code finds it; `plan_ladder.py` copies nothing; the emitter copies the module into the package as `<model>/custom/<stem>.py` with a `kind: support` map entry and the builder resolves `code_ref` there, so the bundle's pinned package tree carries it) and `params.out_shape` (declared, checked by the smoke pass), may only carry `source: user:…`, are marked *unverified* in the layer, and the compiler runs their forward pass on a batch of the declared shape so a wrong shape fails here and not in epoch 1.

## 3. The compiler (`scripts/compile_spec.py`) and the backend emitter (`scripts/emit_backend.py`)

`python3 scripts/compile_spec.py --spec netspec.json --model <model.html> [--pipeline <pipeline.json>] [--backend <name>] --check-only` validates: the schema; that every block type, loss, optimizer, schedule and metric is one the named backend's `coverage.json` lists (`--backend`, default the spec's); every `source` against the layers and the blueprint run; the structural rules — the head's `out` and activation match the catalog's task row for `task.kind` (one logit for binary, `k` for multiclass and multilabel, `k−1` cumulative for ordinal, `1` linear for regression (`Q` under the `quantile` loss), `horizon` for `forecast` (× `Q` under the quantile loss), `recon_dim = n_numeric + Σ cardinality` of the embedded nominals for reconstruction (unsupervised, and anomaly under the `reconstruction` or `vae` loss), `z` for `deep-svdd`; the base task's head, read from `task.base_kind`, on a windowed sample for the `sequence-*` kinds), the loss matches the task row and the head (`bce_with_logits` with a `none` head, never a sigmoid twice; `cross_entropy` with a `none` head; `mse`/`huber` with a linear head), `data_contract.input_dim` equals the number of columns in the shaped manifest's output schema minus the label and the key columns (`data_contract.keys`), every nominal column (nominal per `geometry:typing`, still one column per `shape:manifest/output_schema`) is either embedded by a block or already one-hot per the `encode` step's record in `shape:manifest/steps`, and an embedded column's `cardinality` equals the encode step's `unseen_category_id + 1` (the reserved row is what an unseen category maps to at inference), a sequence family is used only when `data_contract.sample.shape` is `window` — with `length`, `stride` and (for `forecast`) `horizon` declared and sourced, as `_sample_window_example` shows — and the shaper's split is `time`, `early_stopping.monitor` and `metrics.selection.monitor` name a declared metric on `valid`, the test part is sealed, the batch size does not exceed the training rows, the budget is stated. It also checks the spec against the blueprint's `feature_contract` (`input_dim`, `label` must agree; the blueprint's `pipeline.json.input.shape_manifest_digest` — and the spec's own `input.manifest_digest`, the same digest under the spec's name — must equal the digest of the shaped `manifest.json` **file** as the shape layer records it (`shape.manifest_digest`; one definition for the blueprint, the compiler and the emitted `FeatureContract`) — a mismatch is `ERROR: blueprint older than the shape — re-run /blueprint --mode pipeline`, because the emitted code raises on it at the first load and a warning here would only move the crash to `/vega-train`) and reads `serving.mode` (a `stream` mode requires a windowed sample; an `online` mode with a latency forks a heavy family, quoting the latency — `family-catalog.md` §2: the blueprint settled the latency, not the family). And it reads Network stances: a spec that contradicts a stance (a family the user declined, a loss the user declared) is refused unless a `user:` source overrides it and says so.

The compiler emits each check under a rule id with the clause it enforces (`compile_spec.RULES`): `P0` the schema and the required keys, `P1` every choice carries a resolving source, `B1` no framework name outside `backend`, `T1a`–`T1e` the task (a catalog row; the head; the loss; the monitors name declared valid metrics; the task fields), `S1` the test part is sealed, `D2a`–`D2b` the inputs, `G1a`–`G1d` the blocks (known types; a family outside the catalog on known blocks; a catalog family on a combination `family-catalog.md` §7 names as not admitted refused — the table defines the cells the matrix runs, and only those named refusals are compile errors: a catalog family on another combination outside the table compiles — W2 warns on a non-graph family over a `graph` sample — and is no admitted cell, so nothing claims the matrix covered it; residual widths or a projection; custom blocks user-sourced and declared), `G2` the shape walk, `W1`–`W3` windows, graphs and the future, `R1` the batch, the budget and the normalisation, `B2` the backend's coverage, `D1a`–`D1d` the blueprint (required; the feature contract agrees; `serving.mode` is a force on the family; a posture overruled says so), `K1` the ports this stage needs are drawn, `M2` the Network stances are honoured. The sample-shape and task rules in full:

- **W1 — windows.** A catalog sequence family, or a `sequence-*` / `forecast` task whatever its family, needs `sample.shape == "window"` on a `time` split, with `length ≥ 2`, `stride ≥ 1` and `horizon ≥ 1` iff `forecast` (absent otherwise), each sourced; `series_by` and `order_by`, when set, exist in the output schema and are not features; `context` is `previous-part` or `none` with a source; `autoregressive: true` only on `forecast` (`ERROR:` on any other task); `season ≥ 2` when set.
- **W2 — graphs.** A graph family (`sample_shape: graph` in the catalog — `gcn`, `graphsage`, `gat`, `gin`) requires `data_contract.sample.shape == "graph"`, an `edges` entry in the manifest's `outputs.files` that `sample.edges` names (equal paths), a manifest `graph` block (`shape:manifest/graph`) whose `level`, `graph_id` and `directed` agree with the sample, a declared `sample.protocol`, and a `graph_pool` block **iff** `sample.level == "graph"` (a `graph_pool` at node level, or its absence at graph level, is `ERROR:`; graph level also requires `sample.graph_id`, and `gin` requires graph level). `batching` is `full`, `sampled` or `graphs`, `graphs` iff graph level; `sampled` requires one `neighbours` entry per conv block. `exposure` is present iff `protocol: transductive`, and `protocol: transductive` without a `user:` source is `ERROR:` — the test nodes' features would be seen without anyone having said so. A non-graph family on a `graph` shape is `WARN:` — the edges are ignored, and the marker says so — except the `linear` floor, whose `floor_shapes` name `graph`. A graph block (`gcn_conv`, `sage_conv`, `gat_conv`, `gin_conv`, `graph_pool`, `edge_dropout`) outside a `graph` shape is `ERROR:` (there are no edges to read).
- **W3 — the future.** A bidirectional recurrent block (`rnn`, `gru` or `lstm` with `bidirectional: true`, hence the `bi-*` families) on a `forecast` task, or under a blueprint `serving.mode` of `stream`, is `ERROR:` — the block reads the window's future, which neither setting has at inference. The marker names the block id and the setting that forbids it.
- **G2 — the shape walk.** A torch-free walk over the blocks with the catalog's shape rules: on a window the step axis is reduced before the head (`pool`, `flatten`, `attention` with `pool: true`, `attention_pool`, or a recurrent `return` other than `all`); on a graph no convolution follows `graph_pool`, and nothing reduces over the nodes at node level; on rows no sequence block appears; an `embedding` placed before a `feature_tokenizer` is refused (the tokenizer embeds the nominals itself). `ERROR:` — the smoke pass would fail later with a less useful message.
- **T1b — the head** (the structural rule above): `recon_dim` under the reconstruction and vae losses, any positive `z` under `svdd`, `k − 1` for ordinal, `H` (× `Q`) for forecast, the base kind's for `sequence-*`. **T1e — the task fields**: `sequence-*` needs a `base_kind` that `sequence_map` sends to `kind`; `multilabel` needs `classes` and `label_format`; `binary`, `multiclass` and `ordinal` need `classes`; an `anomaly` task with a label needs `positive`.
- **D2a / D2b — the inputs.** `input_dim` equals the output schema minus the label minus the keys; every nominal is embedded, one-hot, or covered by a `feature_tokenizer`.
- **B2 — the backend.** Every block, loss, optimizer, schedule and metric is one the backend's `coverage.json` lists; a block its `planned.blocks` carries is refused as planned in that backend.
- **R1 — batches.** `training.batch_size == "full"` iff `sample.batching == "full"`; an integer batch is at most the training targets (rows, windows, seed nodes or graphs, from the manifest's counts); the budget is stated.
- **R2 — one declaration, live paths.** `regularization[]` is the only place dropout, weight decay, label smoothing and gradient clipping are *declared* (`kind`: `weight_decay`, `dropout`, `label_smoothing`, `grad_clip`; any other kind is refused, as no emitted code reads it). Each kind has live paths — where its value sits when nothing declares it: `optimizer.params.weight_decay`, `loss.params.label_smoothing` (a loss that takes it: `cross_entropy`), `training.grad_clip`, and for `dropout` the `p` of a `dropout` block and the `dropout` of a `transformer_encoder` or of an `rnn`/`gru`/`lstm` of two or more layers (one layer reads none) — every such block inside a block `where` names (a composite covers its `inner`), or every such block when `where` is absent. **The emitted code reads the declaration** (`domain.Regularization`: the optimiser's weight decay, the loss's label smoothing, the clipping bound and every dropout rate the builder sets) and a live path only where no declaration covers it; `compile_spec.py --out` writes the spec with the declared values derived into the live paths, and the emitter's `spec_snapshot.json` lists under `read_paths` the regularization paths the code reads — each declaration it reads (`regularization[kind=<k>]/value` for the first of its kind, `regularization/<i>/value` for each) and every live path no declaration covers — and under `_resolved.regularization` the live paths a declaration *shadows* (`shadowed_paths`) and the value each covered one trains with (`live_values`). The compiler refuses a live path set beside its declaration with a different value, two declarations of one kind that differ (two dropout declarations over one block), and a value out of range (dropout and label smoothing in [0, 1), weight decay ≥ 0, a clipping bound > 0 or `null` for none); the same copies with equal values, a declaration that reaches nothing (a `where` naming no block, label smoothing under a loss that takes none) and a `p`-less dropout block no declaration covers are WARN. The spec states each value **once**, in `regularization[]` — no `weight_decay` in `optimizer.params`, no `p` on a covered dropout block (the example above): a copy, even an equal one, would be refused the moment a rung moved the declaration. This is what makes `defaults_to_test` honest: a delta on `regularization[kind=dropout]/value` moves the weights, because there is no dead copy for it to land on — and `plan_ladder.py` refuses a rung whose regularization delta path is not in `read_paths` (`ERROR: dead delta — no emitted code reads <path>`; a shadowed live path is the case it names), so a rung can never train a run bit-identical to its baseline.

**What is a fork.** A choice is surfaced as a `FORK:` when it has alternatives and nothing upstream settled it: a `vega:default` or an `analysis:` choice memory does not settle, and the family when the blueprint's posture was `auto-resolved`. A `blueprint:`, `geometry:` or `shape:` choice was settled by its owning stage (the blueprint's bet, the geometry layer's partition and typing, the shaper's recipe): it is shown with its alternatives and its source, and changing it is a re-run of that stage, never a fork here. **Forks the sample raises.** Beside the four decision-family forks, a window or graph sample raises the fork points of `family-catalog.md` §5, each with its `--unattended` answer: `context` and `autoregressive` (architecture; the default, applied and marked), `series_by` (architecture; asked only when the shaping record names no series key, and unattended `null` with `WARN: windows may cross series — no series key in the shaping record`), `protocol` (architecture; never asked unattended — always `inductive`, because `transductive` needs a `user:` turn), `batching` (optimization; the default). Every such default lands in `defaults_to_test`, except `protocol`.

`python3 scripts/emit_backend.py --spec netspec.json --backend pytorch --pipeline <pipeline.json> --out <run-dir>/` writes, from the spec and the blueprint's world model, the package `code-contract.md` §2 describes — one sub-package per blueprint module, `ports.py`, `domain.py`, `blueprint-map.json` — whose adapters are the files the rest of this contract names (re-exported under these names by the package's `__init__.py`):

- `<package>/model/network.py` (`model.py` for short) — the network, one class, with the backend's block implementations copied into the package — spliced, only the segments the spec's block types need, into the support files `<model>/blocks_core.py`, `blocks_seq.py`, `blocks_graph.py` and `blocks_gen.py`, beside `builder.py`, `readout.py` and `assemble.py` (one template generation ships, `v2.3`; the emitter refuses a template that still carries the older generation's placeholders) — the package imports the framework and its own `domain` and `ports`, nothing of the skills, because `/vega-pack` copies the package into a bundle that must run alone; `build_model(spec) -> model` per the backend contract (`build_model = Network.build`);
- `<package>/ingestion/data.py` (`data.py`) — loaders from the shaped parts named in the spec: it reads `train` and `valid` and **raises on any request for `test`**; the one door to the test part, `load_sealed_part`, demands the token that only `/vega-eval`'s seal file carries (the seal is code plus one file, and the file does not exist before the evaluation);
- `<package>/training/loop.py` (`train_loop.py`) — the plain loop: forward, loss, backward, clip, step, schedule, per-epoch metrics on train and valid, early stopping, checkpointing, and the per-epoch record of loss, metrics, learning rate, gradient norm (global and per named block), weight norm, update/weight ratio — written to `history.jsonl` by `/vega-train`'s trainer, which imports this module;
- `<package>/model/metrics.py` (`metrics.py`) — the backend's metric functions, copied into the package so the trainer, the evaluator and the notebooks import one file from where they run;
- `spec_snapshot.json` — the spec verbatim with the backend's resolved defaults filled in (so a reader sees `eps`, `momentum`, the schedule's per-epoch values) and the backend's `determinism.tolerance`;
- `requirements.txt` — the backend, its minimum version, and nothing the code does not import;
- `ports.py`, `domain.py`, `blueprint-map.json`, and the adapters of the other blueprint ports (`model/store.py`, `evaluation/evaluate.py`, `serving/predict.py`, `serving/monitor.py`) per `code-contract.md` §2 — emitted from the backend's templates, which is where the *Effective Java* rules of `code-contract.md` §4 live.

Every emission passes the **conformance gate** of `code-contract.md` §5 (the mechanical check C0–C14, refusing on any finding, then `/architect --report-only --baseline`, then `/improve --report-only` on the package, whose structural or divergence findings two of three independent audits reproduce are confirmed and advisory — unattended a `WARN:` and an open item for `/architect` and `/improve`, attended a `FORK:` the user answers) before a layer may be written.

With `--smoke` the emitter builds the model, runs one forward pass on a real batch from the train part, and writes `smoke.json`: `params_total`, `params_trainable`, `per_block` (id, params, out_shape), `madds_per_sample` (per anchor on a window, per target node or per graph on a graph, named by `madds_unit`), `madds_unit` (`row`, `anchor`, `target_node` or `graph`), `forward_ok`, `out_shape`, `device`, `backend_version`, `schedule_lrs`, `loss_formula`, `sample` (the window's length, stride, horizon, context and autoregressive flag with the series count, the train and valid window counts and the valid rows left unscored; the graph's level, protocol and batching with the train and valid views' node, edge and target counts, the test edges withheld and the exposure) and `init_notes` (the init scheme, and for a regression-family head — regression, sequence-regression, forecast, quantile — the `target_affine` it ends on: `y = z · scale + shift`, per output, horizon step or quantile channel, the train target's mean and standard deviation measured on the train part only, held as buffers in the checkpoint, so the network learns in standardised units while the loss, the metrics, the stored predictions and serving read raw units; `null` for the other heads) — the numbers the `architecture` layer shows. Every count is the smoke pass's; the layer computes none. A shape mismatch, a NaN on the first pass, or an unknown block type is `ERROR:`.

The backend is a plug: `backend-contract.md` says what any backend must emit; only `pytorch` ships. The spec never contains a framework name outside `backend`, and `backend.hints` is the one place backend-specific settings may live (they are shown in the layer as *hints*, never as decisions). Framework words in this contract's prose (`nn.Module`, `optimizer.step()`) describe the shipped backend, not the spec.

## 5. Naming, memory, hand-off
