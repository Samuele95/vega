# Vega code contract — the blueprint's world model, made code

The blueprint exists to make a **complete working product**: from ingestion and mapping to a working network, in one architecture. Vega does not emit loose scripts beside that architecture — it emits **the architecture's own modules**, in the module map the blueprint drew, behind the ports the blueprint named, with the value objects the blueprint listed, under the same *Effective Java* discipline the blueprint's findings are anchored to. The network works *in* the model and *with* the model: `model.py` is the adapter of the blueprint's `Model` port, the shaper's preprocessing is the adapter of its `FeatureTransformer` port, the campaign is a set of its versioned artifacts, the bundle is its serving slice. `pipeline.json` carries the world model in machine form (blueprint patch, § *Dataset models*); this contract says how it becomes code and how conformance is enforced.

The example is illustrative — the schema is the blueprint's (`blueprint/SKILL.md` § Dataset models). A port whose adapter a later stage fills carries `filled_by` with that stage (the FeatureTransformer, the Predictor and the Monitor: `/vega-pack`) and no other port does — the emitter refuses either drawing, so the baseline states as pending what the map records as pending; and §4's `depends_on` draws the arrows the package's code takes, the ones `port_surface.py` names (C4 refuses an import against them; a pending module's arrows are taken when its stage fills it). The **names** are the blueprint's, not Vega's: when the blueprint called the transformer port `Recipe` or the store `Registry`, the emitted code uses those names; the **roles** are Vega's closed vocabulary (`DataSource`, `FeatureTransformer`, `Model`, `Trainer`, `Evaluator`, `ModelStore`, `Predictor`, `Monitor`), and the emitter and the conformance check key on `ports[].role` while the code carries `ports[].name`. The roles each stage needs: `net` — `DataSource`, `Model`, `Trainer`, `ModelStore`; `eval` — `Evaluator`; `pack` — `FeatureTransformer`, `Predictor`, `Monitor`. A blueprint that lacks a port with a role a stage needs is not patched by the emitter: the missing role is an `ERROR:` naming it, and the fix is `/blueprint … --concern "<the missing port>"`, because a port invented by the emitter is a designer's choice nobody gated (the blueprint patch tells `--mode pipeline` to draw these eight). **A port's methods are its adapter's.** Each `ports[].signature[]` entry is one method the role's adapter implements — the adapter is the backend's fixed class (`ShapedParts`, `Network`, `ModelRegistry`, `Trainer`, `Evaluator`, `Predictor`, `Monitor`; D1 §4.2), or for the `FeatureTransformer` the recipe's transform-only module — with the adapter's own parameters (names, order, kinds, which ones default): a port that drops, renames or reorders a parameter is an interface its adapter does not keep, and a call written against it binds its arguments to the wrong parameters. A port declares every **port method** of its role (the role table, `ROLE_SIGNATURES`: the methods the stages call through it) and may add another public method of its adapter. **The Model port carries the serving seam**: beside `score`, `predict_proba`, `param_count` and `block_shapes`, its port methods are `head(self, batch: dict)` — the raw head of an assembled batch, without gradients, on the network's device — and `anatomy(self) -> NetworkAnatomy | None` — a read-only view of the staged network (§2's `domain.py`; a view, not a value: its identity is the network's, and the state it reports is read when asked, never a snapshot): its stages aligned with the spec's blocks (ids, stage kinds, types, shapes, the block modules), its readout and sample, its spec digest, the mode and device, the one-class centre, and its own forward; None for a model with no stages. They are what the Predictor and the inspection package read of the network, and all they read: neither calls the network object nor reads its mode, device, digest or parameters off it, and its forward and stage modules are reached only as `anatomy()` hands them over (the block modules read through their inspection surface, R-B3), so anything that implements the port can be served and inspected (the shipped round-trip test proves it on a stand-in carrying the port's methods alone; `tests/test_model_seam.py` reads the serving templates for any other reach). `scripts/port_surface.py --shape <row|window|graph> --task <kind>` prints both lists per role (a method only some shapes or task kinds carry — a graph's `exposure`, a forecast window's `target_scale`, a regression-family head's `train_targets` — is the port's in those packages only) and the package's own interfaces beside the ports; the emitter refuses any other drawing before it writes, by port and method, as the blueprint's §3 (`/blueprint --concern`).

## 2. The emitted package

The backend emits into the run directory a Python package named `pipeline.json.system.package`, one sub-package per blueprint module, plus the two files every module depends on:

```
vega-runs/<ts>/<package>/
  __init__.py  <module>/__init__.py   ← the package and one per module (support entries); a module's `__init__.py` re-exports by name, loaded on first use (PEP 562), the adapter class of each port it owns (and the Model module's `build_model`) and every name that crosses its boundary — the `__all__` of a support file a role of another module reads (`used_by`) or that implements a backend interface (`implements`), a function library also as itself (`metrics`) — so a consumer binds to the module, never to a file the emitter may re-slice, and the other modules' templates import those names from the module (`from ..model import TaskReadout, metrics`)
  domain.py            ← the artifacts the package holds (every `artifacts[]` entry not declared `external`, §3) as immutable value objects (frozen dataclasses with equals/hash by value, static factories, validated on construction); enums for task kind, family, part, batch key; the backend's own value objects (EpochRecord, FitResult, RunContext, BatchPlan, MetricOptions, BaselineContext, NetworkAnatomy — what the Model port's `anatomy()` returns —, and the window or graph plans of the spec's own sample shape only — the emitter keeps the template's shape sections of that shape and refuses a package whose sections leave a name unresolved); a v2.2 name (`TrafficClass`, `ResidentPart`) only when the blueprint still uses it
  ports.py             ← one Protocol per blueprint port (static interfaces, never `@runtime_checkable`: an `isinstance` test against a Protocol checks names, not signatures, so none is offered), docstring = the blueprint's responsibility line and its source tag; beside them the backend's own, marked as not blueprint ports: `ModelBuilder`, `ArtifactExporter`, the surfaces the Trainer and the Evaluator read of a model — `TrainedNetwork` (the Model port and, beyond it, the network's ids, target affine, KL, one-class centre: what a fit trains, a store saves and restores) and `ScoredModel` (`score`, `sample_view`, `row_score`, `head`, which the network and every fitted baseline carry) — and what a fit reads beside the network: `TrainingData` (the DataSource without its sealed door: the train and valid parts, streamed or held) and `Callbacks` (the three optional hooks of `fit`); the Trainer, Evaluator and ModelStore port signatures are typed with them (`fit(model: TrainedNetwork, spec, data: TrainingData, callbacks: Callbacks | None, run)`, `predict(…) -> ScoredPart`, `load(…, build: ModelBuilder, …) -> TrainedNetwork`, `scored(…, model: ScoredModel)`); serving and inspection read no surface beside the port (§1: its `head` and `anatomy()`), so no served-network or inspectable protocol is declared; the TYPE_CHECKING imports are the domain names its signatures use — any name the rendered `domain.py` holds (`held_artifacts.py`), plus the `typing` names `Sequence`, `Mapping`, `Iterable`, `Callable`, `Optional`, `Union`, `Literal` when a signature reads one; a signature that names anything else (a framework type such as `DataFrame` or `Tensor`), that does not parse, or whose method does not take `self` first is refused by the emitter as the blueprint's §3, by port and name
  ingestion/data.py    ← DataSource adapter: class ShapedParts(DataSource) — load_part raises on test; load_sealed_part needs the seal token; open_features_only is the transductive door (netspec-contract §1)
    ingestion/frames.py   support: the part files, their digests and raw row positions
    ingestion/windows.py  support, window shape only: the anchors and their context
    ingestion/graphs.py   support, graph shape only: the edges part, the views, the samplers
  features/preprocess.py  ← FeatureTransformer adapter: a stub raising NotImplementedError("pending: /vega-pack") until /vega-pack copies the shaper's transform-only module here (ingestion reads the shaped parts meanwhile)
  model/network.py     ← Model adapter: class Network(Model), built by Network.build (alias build_model) through NetworkBuilder — one small builder method per block type, dispatched by a table; `head(batch)` and `anatomy()` are the serving seam (§1)
    model/builder.py      support: the NetworkBuilder (spliced segment)
    model/blocks_core.py  support: the prelude and the core blocks; blocks_seq.py, blocks_graph.py, blocks_gen.py only when the spec uses one of their block types (spliced segments)
    model/readout.py      support: TaskReadout, the one score contract (backend-contract §1.2)
    model/assemble.py     support: the SampleAssembler the Predictor batches raw rows with
    model/metrics.py      support (FP): the metric functions, each effective kind's reading of its score (the numpy half of `TaskReadout`, `readout.scores`) and the one scoring pass (`ScoringPass`) the Trainer's valid numbers and the Evaluator's scored parts are made by
    model/export.py       support of the ModelStore: the exporter (ONNX, TorchScript) and its parity check
    model/baselines.py, model/baselines_extra.py  ← the baselines of eval-contract §4 (map role: baseline, `implements: ScoredModel`, no port): one recipe class with a form composed in, whose `fit` returns a fitted baseline (a `ScoredModel`) or a refusal and changes nothing; emitted when the blueprint draws an Evaluator
    model/custom/<stem>.py  support, only for a `custom` block: its code_ref, copied in (netspec-contract §2)
  <module>/store.py    ← ModelStore adapter: class ModelRegistry, in whichever module the blueprint gives the ModelStore role (`registry/`, `model/`, …): save(model, path, spec, *, epoch=None) -> Checkpoint / version(path) -> Checkpoint / load(ref, spec, build, *, expected_digest=None, run_dir=None) — the spec and the builder required, the options by keyword — path-addressed, digest-verified, the weights digest carried inside the checkpoint file so it survives a rename. Every template header names its module from the map ({{MODULE_<ROLE>}}), never a fixed path
  training/loop.py     ← Trainer adapter: class Trainer(ports.Trainer) — fit is a loop over _epoch, _epoch over _step, each a method a screen can hold; the callbacks, the budget and the recorder are collaborators, not branches
    training/losses.py (spliced segment), optim.py, record.py, engines.py, graph_engines.py (graph shape only)   support of the Trainer
  evaluation/evaluate.py  ← Evaluator adapter: class Evaluator(ports.Evaluator) — only the port (load through the store, score through the seal, metrics through metrics.py); the protocol — seal file, baselines, bootstrap, slices, robustness — is /vega-eval's own scripts/evaluate.py, which calls this adapter
  serving/predict.py   ← Predictor adapter: a stub until /vega-pack completes it (it becomes the bundle's predictor)
  serving/monitor.py   ← Monitor adapter: a stub until /vega-pack fills it from pipeline.json.monitoring[]
  blueprint-map.json   ← §3 (`generation: v2.3`)
```

**The forge emits no inspection code**: its templates (`backends/<name>/templates/*.py`) hold no inspection module, and the inspection package lives only under `templates/serving/package/inspection/`, which only `/vega-pack` renders into a bundle — a campaign package carries none. Which support files a package holds follows from the spec (`emit.py` `SUPPORT_FILES`, each with its `when`): a row spec has no `windows.py`, `graphs.py` or `graph_engines.py`, and a block file is emitted only when the spec uses one of its block types. **In a bundle**, `/vega-pack` renders the serving support modules into the Predictor's module beside `predict.py` and `monitor.py` — `records.py`, `values.py`, `heads.py`, `guards.py`, `samples.py`, `graphs.py` and, unless `--no-inspect`, the `inspection/` package (the stage graph, its readers and probes, the capture, the targets, the attribution and the `NetworkInspector` facade; `inspect-contract.md` §2) — each a `kind: support` map entry with `used_by: ["Predictor"]` and `source: "the vega-pack serving templates"`; and it writes `serve/`, `tests/` and `predict.py` outside the package as entrypoints (`bundle-contract.md` §1, §7.1). The ingestion, training and evaluation modules stay in the map with `out of scope: <reason>` (in a `serving` bundle).

Every Vega contract names emitted files **package-relative** (`<package>/model/network.py`, `<package>/ingestion/data.py`, `<package>/training/loop.py`, `<package>/model/metrics.py`); where a contract's prose says `model.py`, `data.py`, `train_loop.py`, `metrics.py` for short, it means these files, and every digest, copy and import is of the package path — no shim files exist at the run root. **Every port adapter the backend's templates emit is a class** that implements its Protocol — `class ShapedParts(DataSource)`, `class Trainer(ports.Trainer)`, `class Evaluator(ports.Evaluator)`, `class Predictor(ports.Predictor)` — because a port is a type (EJ-20) and the thing that satisfies a type is an object with a state it guards (the seal, the fitted parameters, the device, the recorder), not a namespace of functions that pass that state around as arguments. The one adapter the backend does not emit is the `FeatureTransformer`: the forge emits only its `pending: /vega-pack` stub, and `/vega-pack` replaces it with the shaper's transform-only module (`dataset-shaper/references/shape-contract.md` §2), a generated program whose public functions `transform`, `edges_for` and `edges_within` *are* the port — the inference-graph rule needs them as functions a caller passes raw rows to — so C14 holds it to the Protocol structurally (C10) and to C11–C13, never to the class rule; no template of the forge may use that exemption. Free functions are otherwise allowed only as `_prefixed` pure helpers in the adapter's own module (a metric, a window cut, a digest), and `model/metrics.py` — a library of pure functions with no state — is the one module whose paradigm is `FP`. Correspondingly, **`pipeline.json.modules[].paradigm` is `OOP` for every module that owns a port**; the blueprint (its patched SKILL.md) writes it so, and `conformance.py` C14 refuses a package whose port adapter is not a class or whose module declares `FP` while owning a port. A module the blueprint did not draw is not emitted; a port the blueprint drew that a later stage fills is emitted as its Protocol with a `NotImplementedError` adapter whose message names the stage (`pending: /vega-pack`), and the map says the same.

In a bundle, `/vega-pack` rewrites the copy: the ports the slice leaves behind become `"status": "out of scope: <reason>"` (and so do the support files of those modules), `"package_slice"` says which shape was packed, every serving support module it rendered is an entry such as `{ "file": "serving/inspection/inspector.py", "module": "serving", "kind": "support", "used_by": ["Predictor"], "source": "the vega-pack serving templates", "status": "implemented" }`, and `entrypoints` lists every served file it wrote outside the package — `serve/*.py`, `serve/static/index.html`, `tests/*.py` — each with the ports its handlers call (`"calls": ["Predictor"]`, `["Monitor", "Predictor"]`, or `[]` for a module that calls none).

**The artifact roster.** Every entry of `pipeline.json.artifacts[]` has exactly one home, and the map says which. It is **held** — a name the emitted `domain.py` defines (a class, or an alias of one), listed in the `domain.py` entry's `artifacts` in the blueprint's order — or it is **external**: the blueprint declares that a stage other than the forge holds it outside the package, `"external": { "owner": "<stage>", "where": "<where it lives>" }` on the artifact's entry, and the emitter neither writes it into `domain.py` nor drops it, but records it in the map's `external_artifacts` with its owner and where it lives. The campaign is the usual external artifact (`/vega-train`'s campaign directory, which the package only touches through `RunContext` and the store's `save(path=…)`); the shaper's recipe, its fitted parameters and the shaped parts are `/dataset-shaper`'s, the seal and the verdict `/vega-eval`'s, the bundle's service values `/vega-pack`'s. `owner` is one of `/dataset-forge`, `/data-lens`, `/dataset-shaper`, `/blueprint`, `/vega-train`, `/vega-eval`, `/vega-pack`, `/vega-show` — never `/vega-forge`, whose product *is* the package — and `where` is required: a declaration that does not say where the artifact lives accounts for nothing. The roster is derived from the blueprint and the `domain.py` being emitted (`scripts/vega_roster.py`, which the emitter writes and C6 reads back), never from a list of the emitter's: a blueprint artifact `domain.py` does not define and the blueprint does not declare external is an `ERROR:` naming it — the emitter refuses before it writes anything, because an artifact silently left out of the roster is the divergence `/architect --baseline` exists to find — and so is an artifact declared external that `domain.py` defines (the declaration is false), an owner outside that set, a declaration without `where`, and a name listed twice. The fix is the blueprint's: declare the artifact external (`/blueprint … --concern "<artifact> is held by <stage>"`), or, for a value object the package should hold, the backend's `domain.py` template. `backend_artifacts` lists the backend's own value objects the blueprint did not list — every other name `domain.py` holds an artifact under (value objects, enums, aliases: `held_artifacts.py`'s list), so each value object of the package is declared exactly once, and C6 refuses one the map names nowhere (one source per name: a blueprint that lists `FitResult` finds it under `artifacts`). The `ports.py` entry lists, under `backend_protocols`, the package's own interfaces it declares beside the blueprint's ports. What an interface's implementation writes has a home too: the `model/export.py` entry's `output` says the exported files are `/vega-pack`'s, under the bundle's `exports/`, pinned by `MANIFEST.exports` — the package holds the converter, never the converted artifact.

Every emitted file has an entry: an **adapter** entry (a port and a role), or a **support** entry (`kind: support` — `domain.py`, `ports.py`, the `__init__.py` files, `model/metrics.py`, and every file an adapter delegates to, with `used_by` naming the roles that import it: the files that implement no port). Files a stage writes *outside* the package — the bundle's `predict.py` CLI, `serve/`, `tests/` — are **entrypoints**: listed with the port they call, scoped out of the mechanical check (which reads the package) and in scope for `/architect` (which reads the directory). `unmapped` must be empty: a file with neither an adapter, a support nor an entrypoint entry is a designer's choice the emitter is not allowed to make. `domain` is a module of the map with no ports and no dependencies; `domain.py` and `ports.py` are its files, and every module may import them — the two implicit arrows the mechanical check allows beside `modules[].depends_on`. Every blueprint port has an entry with `status` `implemented`, `pending: <stage>`, or — in a bundle, for a port the serving slice does not carry — `out of scope: <reason>`. Extra implementations of a port exist only where the map marks `role: baseline`. `entries[].file` is package-relative (the map sits inside the package and carries `package`); the layer's digest tables and the bundle manifest prefix it with `<package>/`. The layer shows the map as a table; `/vega-pack` copies it into the bundle with the statuses updated; `/architect` reads it when it diffs the code against the blueprint.

## 4. The design rules the emitted code obeys — anchored, not restated

The rules are the *Effective Java* items the blueprint anchored its pipeline findings to (`pipeline.json.anchors`, within the 43-item `architect` set of the `effective-java` skill, which is the single source of their text), plus EJ-49 from the `improve` set for the boundary checks; this list names the item and the concrete form it takes in the emitted code, nothing more:

| item | in the emitted code |
|---|---|
| EJ-17 minimize mutability | every artifact in `domain.py` is a frozen dataclass; a spec, a contract, a checkpoint record, a metrics record never change after construction; the fitted parameters are read once and held immutably by the adapter that uses them |
| EJ-20 prefer interfaces | every port is a `typing.Protocol`; adapters depend on ports, never on each other's classes |
| EJ-64 refer to objects by their interfaces | `Trainer(store).fit(model: TrainedNetwork, spec: NetSpec, data: TrainingData, callbacks: Callbacks | None = None, run: RunContext | None = None)` — the backend contract's `fit` (the budget, the checkpoint directory and the gradient sampling travel in the `RunContext` value object, so no port method takes more than five parameters; the ModelStore the checkpoints are written through is the Trainer's collaborator, given to its constructor), typed by the backend's interfaces and by the `NetSpec` value object; **no port collaborator is typed `Any`**, and a dict never crosses a port: `NetSpec.from_dict` / `NetSpec.require(obj)` convert **once, at the entry points** (`emit_backend`, `trainer`, `evaluate`, `nb_emit`; the domain does no IO), and `require` refuses a dict by name; a spec's sections are read through its typed views (`training`, `loss`, `optimizer`, `schedule`, `selection`, `inputs`, `hints`), never by string key in an adapter; no adapter's signature names another adapter |
| EJ-2 builder for many parameters | `build_model(spec)` composes the network through a builder that reads the spec's blocks in order; no constructor with a dozen positional parameters |
| EJ-1 static factories | `NetSpec.from_dict(d)`, `Checkpoint.of(path, digest, …)`, `Metrics.from_predictions(…)` — the names say what they validate |
| EJ-10 / EJ-11 equals and hashCode | value objects compare by value (the dataclass's, with digests as identity where the artifact says so) |
| EJ-15 minimize accessibility | module-private helpers are `_prefixed`; the package `__init__.py` exports the adapters and the ports, nothing else |
| EJ-18 composition over inheritance | the network is composed of blocks; no adapter subclasses another adapter; the residual block wraps, never extends |
| EJ-34 enums instead of constants | `TaskKind`, `Family`, `Part`, `BatchKey`, `StopReason`, `Verdict` (a monitor reading's outcome) are enums; a string task kind or verdict never crosses a port — a `DriftReading` carries `check`, `concern`, `title`, `verdict: Verdict`, `value`, `reference` as typed fields, never as string-keyed pairs in a tuple |
| EJ-49 check parameters for validity (improve set) | every adapter validates its inputs at the boundary it guards — the `DataSource` refuses the test part, the `Predictor` validates rows against the schema — and raises with the offending name |
| EJ-51 design method signatures carefully | a method does one thing a reader can hold: **≤ 30 statements** and **≤ 5 parameters** beyond `self` (a sixth becomes a value object from `domain.py` or a collaborator); `fit` delegates to `_epoch`, `_epoch` to `_step`; the builder dispatches on block type through a table of small methods, never one long `if/elif` — Bloch's *break the method into pieces* is the mechanical rule C11–C12 |
| EJ-15 / EJ-25 cohesion and one type per file | a class is **≤ 200 lines**, a module **≤ 400** (C13); an adapter module holds its adapter class and its `_prefixed` helpers, imports and constants, nothing else (C14) |
| SOLID-S single responsibility (the non-EJ anchor the `architect` and `improve` skills accept) | the recorder records, the budget counts, the callbacks notify, the loop loops — a collaborator per concern, injected (EJ-5), so that no method grows by absorbing a neighbour's job |

The build keeps these rules in the backend's **templates** (`backends/<name>/templates/`) and in the spliced segments of `blocks.py`, `builder.py` and `losses.py`: the emitted code is the template plus the spec, and a design defect in emitted code is fixed **in the template**, never in a run's copy — the same rule the spec has (a change is a change to the source, then re-emit). The size rules apply to the templates *as emitted* — a spliced builder or loss segment counts in the method it lands in — which is why the templates are written as classes with small methods and a dispatch table, not as one function that grows with every block the catalog adds.

## 5. Conformance — the gate every emission passes

Three checks, in this order, before any layer is written (the first blocks on any finding; the second and third are the **judgement half**: their findings are reproduced or recorded by a quorum of audits, and a finding the audits confirm is **advisory** — *Reproduced, or recorded* and *Advisory* below):

1. **Mechanical** — `python3 <vega-forge>/scripts/conformance.py --package <dir> --pipeline <pipeline.json> --map <blueprint-map.json> [--bundle] [--entrypoints [ROOT]] [--size-severity warn|error] [--json]`: every file parses (**C0**, named with its line); every blueprint port has exactly one primary adapter, or a `pending: <stage>` entry, or — with `--bundle` — an `out of scope: <reason>` entry; extra implementations only where the map marks `role: baseline`; every file in the package has an adapter or a support entry and `unmapped` is empty; the import graph of the package respects `modules[].depends_on` plus the two implicit arrows to `domain.py` and `ports.py` (an import against the arrow is a violation, named with the file and line); adapters import ports and `domain`, never other adapters; every class in `domain.py` is a frozen dataclass, an enum, or a subtype of an immutable builtin (`tuple`, `frozenset`, `str`) with `__slots__ = ()` — the tagged tuple `_FrozenMap` that keeps a mapping distinguishable from a list of pairs after `to_dict()` / `from_dict()`, so a value object compares equal to itself round-tripped (EJ-10/11) — and every blueprint artifact is accounted for as §3's roster says: a name `domain.py` defines and the map's `domain.py` entry lists, or declared external with its owner and recorded so in the map's `external_artifacts` (a held artifact the entry omits, a name the entry lists that the blueprint does not hold there, an external artifact the map does not record with the blueprint's owner and `where`, or one it records that the blueprint does not declare, is refused, as is a blueprint artifact with no home); no module-level mutable state; the `DataSource`-role adapter raises on the test part (`load_part` is read on the adapter class or at module level); the `Model`-role adapter's `build_model` is the only constructor of the network (a module-level `def build_model`, or the alias `build_model = Network.build`, and then `Network(...)` is called nowhere but inside `Network.build`); a `FeatureTransformer`-role adapter satisfies the Protocol structurally (`transform(df_raw, history=None) -> DataFrame`, a function or a method — which the shaper's emitted module does without knowing `ports.py`) — these are **C1–C10**; then the **size discipline, C11–C14**, measured on the AST, never on the text (`conformance.measure_module(tree, rel)` and `conformance.size_findings(tree, rel)` are the functions other scripts call):
   - **C11** no function or method longer than **30 statements**. A statement is an `ast.stmt`, counted recursively, without the docstring; blank lines and comments are not statements; `elif` is the `If` the AST makes of it; a nested `def` (or `class`) counts once in its parent and is measured on its own.
   - **C12** no function or method with more than **5 parameters** beyond `self` / `cls` (a `staticmethod` has none to discount); `*args` / `**kwargs` count one each and are allowed only in a `_prefixed` helper — a `_`-prefixed def or class, or anything nested in one; a dunder is a public protocol method, not a helper.
   - **C13** no class longer than **200 lines** (first decorator to last statement) and no module longer than **400** (line 1 to its last statement); `domain.py` and `metrics.py` are exempt from the module rule by file name — a set of small value objects and a library of small pure functions are long by count, not by cohesion — but never from C11–C12 (the page's strings table carries the same exemption under the page's own rule).
   - **C14** every module that owns a port is declared `OOP` in `pipeline.json.modules[].paradigm`; every `implemented` port adapter of the map is a **class**, and its module's top level holds only that class, `_prefixed` helpers (defs and classes), imports (an `if TYPE_CHECKING:` guard included), UPPER_CASE or `_prefixed` constants, dunders such as `__all__`, and the one alias `build_model = Network.build`, which satisfies C9 as well. The adapter class is the one whose base names the port or the role (`class ShapedParts(DataSource)`), else the role's template class (`ShapedParts`, `Network`, `ModelRegistry`, `Trainer`, `Evaluator`, `Predictor`, `Monitor`) or the port's own name, else the one public class `__all__` exports. The one-class rule is the adapter modules' only: `kind: support` files, `role: baseline` modules (the baselines: scored models no port is implemented by, a recipe and its forms split across two files) and entrypoints are exempt from it, not from C11–C13; a `pending: <stage>` stub is read by C14 once the stage that fills it marks it `implemented`. The **`FeatureTransformer`-role module is exempt from the class rule and the top-level rule** in every status, and held to C11–C13 like any file: it is the shaper's transform-only module, whose public module functions `transform`, `edges_for` and `edges_within` *are* the port (the inference-graph rule, R-A3; D2 §4.4), so a class there would break the interface the round trip and the service call; C10 reads its shape structurally instead. The module that owns it is still declared `OOP` (the paradigm rule above is the blueprint's declaration, not the adapter's shape).

   Each violation names the file, the line, the measured value and the anchor, one line each, in the words the gate ships — C3: `<file> has neither an adapter, a support nor an entrypoint entry — a file nobody mapped is a designer's choice the emitter is not allowed to make`; C14 on a second public class beside an adapter: `… a public class that is not the <role> adapter class` (so an inspection file packed without its map entry fails C3 alone, and a `NetworkView`-like second public class in the Predictor's module fails C14): `C11 training/loop.py:88 fit — 131 statements > 30 — EJ-51` (C11 and C12 anchor EJ-51; C13 EJ-25; C14 EJ-20 for a paradigm or a missing class, EJ-25 for a second public name, EJ-15 for a public function that should be `_prefixed`). A C0–C10 violation is `ERROR:` for the stage. C11–C14 are `ERROR:` like every other check: `--size-severity error` is the default (the templates meet the limits: the backend coverage matrix emits every admitted cell with zero C11–C14 findings), so every stage that runs the gate — `/vega-forge`, `/vega-train` on re-emitted code, `/vega-pack` on the bundle — refuses a size finding without passing any flag. `--size-severity warn` exists only for surveying code that is not held to the discipline (a skill's own scripts swept with `--size-only`); it reports each finding as a `WARN:` line plus one line saying the default would refuse them, and no stage passes it on an emitted package or a bundle. The thresholds are the contract's and are not flags: a template that needs 31 statements needs a second method. `--entrypoints [ROOT]` also applies C11–C13 to the files a stage writes outside the package — `predict.py`, `serve/**/*.py`, `tests/**/*.py` and every `entrypoints[].file` of the map, under ROOT (default: the package's parent, the bundle root) — and `/vega-pack` passes it on the bundle; `--size-only PATH...` applies C11–C13 alone to code that is not an emitted package (a skill's own scripts; a directory stands for every `*.py` under it); `--json` prints one document and nothing else — `{mechanical, markers, size: {severity, counts, findings}}`, the markers and the size findings as values — in every outcome, an unreadable input included (its `IO` markers are in the document; only an argparse usage error is plain text). A `--size-only` directory sweep parses the skills' test harnesses (`*/scripts/tests/**`, `vega-show/assets/page/tests/**`) and does not measure them — they are neither emitted nor shipped; a file named on its own is measured. Exit 0, or 2 with the list of violations, or 3 when an input could not be read.
2. **Judgement of the world model** — the stage invokes **`/architect <package dir> --report-only --baseline <blueprint-runs/<ts>/blueprint.md>`** through the runtime's Skill tool (the architect patch adds `--baseline`: the audit diffs the code's world model against the blueprint's §0, §2, §3, §4 and tags divergences). The result is read from its `findings.json`: a finding of depth `structural` (the apply script counts **depth**, not class: a structural-*depth* finding is blocking-class whatever its class) or tagged `divergence` is **blocking-class** — the class the quorum judges — and when the audits *reproduce* it (below) it is **confirmed**: the template is wrong, and the fix goes to the template through `/architect` or `/improve` on `backends/<name>/templates/` (an *apply* run on the templates, then re-emit; never a hand edit of the run's code) — now, when the user answers so attended, or later, as the open item *Advisory* hands to `/architect` and `/improve`; findings of depth `architectural` propose reshaping the blueprint's own world model, which is the blueprint's to change (`/blueprint --concern`), not the template's, and findings of depth `surface` are tactical — both are recorded in the layer as `code_findings[]` with their anchors, justifications and `tool: architect`. Unattended: the architect pass runs with `--report-only` as it does attended; only the apply is a human's.
3. **Judgement of the method-level discipline** — the stage then invokes **`/improve <package dir> --report-only`** through the Skill tool and reads its `findings.json` the same way: a finding of depth `structural` (a design defect in the shape of the code — a class doing two jobs, a method that should be three, a string standing for a type, an ignored exception) is blocking-class, confirmed when reproduced, with the same remedy (`/improve` in apply mode on `backends/<name>/templates/`, then re-emit — never the run's copy) and the same advisory outcome; `surface` findings are recorded as `code_findings[]` with `tool: improve` and are the tactical list the summary hands to the user for the bundle they will own. The mechanical C11–C14 are the floor `/improve` cannot lower; `/improve` is the judgement the floor cannot replace — a method of 29 statements that does two things passes C11 and fails here. Without the `improve` skill, `WARN: improve not installed — method-level discipline judged mechanically only`.

**Reproduced, or recorded** (the judgement half, steps 2 and 3; the user's decisions of 2026-10-11). An open-ended audit of an emitted package raises a different set of findings each time it runs, so a single audit's blocking-class finding is a claim to reproduce, not yet a verdict. Per tool, `scripts/audit_quorum.py` states and applies the rule, and the apply scripts of `/vega-forge` and `/vega-pack` import it:
- **One clean first audit passes alone.** When the first audit reports no structural and no divergence finding, no further audit runs.
- **A first audit that reports one is never judged alone.** Two more **independent fresh audits** of the same code run — each its own `--report-only` run in a fresh context (a subagent or Skill invocation that has not read the earlier audits' findings, given the same scope and, for `/architect`, the same `--baseline`), **one after another**, each writing its own run directory — and the three are judged together: `python3 <vega-forge>/scripts/audit_quorum.py --tool architect|improve <run1> <run2> <run3> [--mode attended|unattended]` (with `<run1>` alone it prints `NEED:` and exits 1 while a blocking-class finding waits for its two fresh audits). The audits are distinct runs (no directory, no **run id** and no `findings.json` given twice) of the same code (the `scope.paths` each run states, read relative to the project, a glob as its literal root: `pkg/**/*.py` is `pkg`); after a re-emit the procedure starts over with a first audit. Any other number of audits is refused.
- **A run id is one audit's.** The run id is the name of the audit's run directory (`.claude/<tool>-runs/<id>`, the UTC timestamp the skill gives it). Two audits started in the same second write one run id — in one project the second overwrites the first, in two copies they are two runs named alike — so the fresh audits never run concurrently, and `audit_quorum.py` refuses two audits that share a run id, at one path or two (exit 3, the judgement `invalid`).
- **Two of three confirm.** Two findings of two audits **report the same thing** when they share a **file location** (a file both name, compared by path components from the file name up, the audited root and line numbers dropped, the baseline's own files — `blueprint-runs/…` — not counted as a location; a finding naming no file matches only a location written the same) **and** share a **principle anchor** (`EJ-64`, `SOLID-D`, `HEX`, …) **or a category** (the finding's `category`, else its `axis`). A report at any depth counts. A blocking-class finding that **at least two of the three audits report** (its own and at least one other) is **confirmed**: the remedy above applies, and *Advisory* says what it does to the run. One no second audit reports is **unconfirmed**: it is recorded — in the tool's `conformance` record and in `code_findings[]` with the audits that reported it — and nothing more.
- **Everything is recorded.** The tool's `conformance` record is `audit_quorum`'s, spliced by the apply script from the runs (never typed): `ran`, `run` (the first audit), `audits[]` (each run's path, the digest of its `findings.json`, its scope, its timestamp and its counts), `audits_required` (1 or 3), `structural` and `divergence` (the **confirmed** findings, each defect counted once — the counts *Advisory* turns into open items), `unconfirmed` (`{structural, divergence}`), `recorded` (the findings that are not blocking-class), `matching[]` (one row per blocking-class finding of any audit: `finding` as `<audit>:<id>`, depth, divergence, files, anchors, category, `reported_by` (the audits), `matched` (the findings that reproduced it), `confirmed`, `counted`, `same_as` for a repeat of a defect counted once), and `rule` (the rule in words), and `advisory` (below); `pending` or `invalid` while the procedure is incomplete — both refuse. Every spliced finding carries its `tool` and its `audit`, and a blocking-class one its `quorum` (`reported_by`, `confirmed`); a confirmed one its `open_item`.

**Advisory** (the user's decision of 2026-10-11, which supersedes the blocking part of the two-of-three rule). The judgement half of every conformance gate — `/architect --baseline` and `/improve --report-only`, here, in `/vega-pack` on the bundle — is **advisory**: its findings still run as the quorum above and are recorded in the layer (every audit, the matching, the confirmed and the unconfirmed findings), and what a confirmed `structural` or `divergence` finding does depends on whether a user is present:
- **Unattended** (`--unattended`): it is a `WARN:` and an **open item handed to `/architect` and `/improve`** — the apply script (passed `--unattended`) writes the `WARN:` into `markers`, the open item into the tool's `conformance.<tool>.advisory.open_items` (`{tool, finding, files, title, reported_by, for: ["/architect", "/improve"], remedy, text}`) and onto the finding in `code_findings[]` (`open_item`); the stage brief's *Open* names each one as `<tool> <audit>:<id>` (`vega/references/brief-contract.md`), and `/vega` copies it into the ledger's **Open**. It **never stops an unattended chain**: the layer is published and the chain continues.
- **Attended**: it is a **`FORK:`** the user answers — **fix now** (the remedy above, then re-emit and the gate again; nothing is published until then), **accept and record** (published as unattended: the `WARN:` and the open item, with the user's answer), or **stop** (the stage ends, nothing published). The stage never answers it; the answer is recorded in the layer's `forks[]` as `{"family": "conformance", "gate": "<tool>", "findings": ["<audit>:<id>", …], "asked": "<the FORK line>", "answer": "<fix now | accept and record | stop> — <the user's words>"}`, naming every confirmed finding of that tool. The apply script (without `--unattended`) refuses a confirmed finding whose fork has no recorded answer, an answer that is a default (`or`), or the answer *fix now* or *stop*.
- `conformance.<tool>.advisory` records the outcome — `mode` (`attended` | `unattended`), `outcome` (`clear` with nothing confirmed, `warn` unattended, `accepted` attended), `confirmed` (the finding keys), `answer` (the user's, attended), `open_items`, and `rule` — and the apply scripts refuse a record whose confirmed findings it does not name, each as an open item (a **malformed record**).

What refuses, then, is **only a procedure that did not run or a record that is malformed**: a first audit's blocking-class finding without its two fresh audits (`pending`), audits that are not one or three distinct runs (directories, run ids and `findings.json`) of the same code (`invalid`), a judgement typed into the layer instead of spliced from the runs, an advisory block that does not carry every confirmed finding — and, attended, the user's *fix now*, *stop*, or no answer. `audit_quorum.py` prints a confirmed finding as `WARN:` and, by mode, the open item (unattended) or the `FORK:` (attended), exit 2; exit 3 is the refusal.

The **mechanical half (C0–C14) is not judged by audits and keeps blocking on any finding**, attended or not: the quorum and *Advisory* apply only to the judgement half. Every product check of the chain keeps blocking too — the briefs, the model validation, the smokes, the round trip, the bundle's tests, the showcase's checks and walk.

The same gate runs in `/vega-train` on re-emitted code (mechanical only, C1–C14 — the templates did not change) and in `/vega-pack` on the bundle's package with `--bundle` (all three: the bundle is the code the user will integrate, `/architect --baseline` on it is the last proof that what ships is the blueprint's serving slice, and `/improve --report-only` on it is the tactical list the user starts from; a confirmed structural finding there is advisory as above, and its remedy — now on the user's *fix now*, or later as the open item — is the serving templates, the serving adapters re-emitted by `pack.py --re-emit-serving`, which touches nothing the evaluation pinned by digest — what it may and may not change, its staging and its refusal are `vega-pack/references/bundle-contract.md` §7.8). Without the `architect` or the `improve` skill installed, the mechanical check still runs and the missing judgement is `WARN: <tool> not installed — conformance judged mechanically only`, carried into the layer and the summary; the layer's `conformance` object records, per tool, the judgement *Reproduced, or recorded* defines (every audit and the matching) with its *Advisory* outcome, or the tool's absence.

## 6. What the blueprint's other keys constrain

- `serving.mode` — `batch` / `online` / `stream` is a source for the family and budget choices (an `online` mode with a stated latency turns a heavy family into a `FORK:` quoting the latency force; `stream` requires a windowed sample) and for `/vega-pack` (`--serve` defaults on for `online` and `stream`; the bundle's `Predictor` exposes the interface the mode implies; the manifest records the boundary interface implemented).
- `training.protocol` — the CV or split protocol the analysis used; `/vega-train` follows it (a k-fold protocol becomes the campaign's `valid` scheme through the `DataSource`) or records `train:protocol-override` with the reason (the shaper's fixed split is the usual one, and it must be said).
- `monitoring[]` — what the analysis found fragile becomes the `Monitor` adapter's checks and `/vega-eval`'s robustness slices.
- `feature_contract` — `compile_spec.py` refuses a spec whose `data_contract.input_dim` or `task.label` differ from it, and refuses (`ERROR`, not a warning) a `pipeline.json.input.shape_manifest_digest` that is not the shaped `manifest.json` file's digest as the shape layer records it — the one definition the blueprint, the compiler and the emitted `FeatureContract` share; the emitted code raises on the same mismatch at its first load, so a warning at compile time would only move the failure downstream.
