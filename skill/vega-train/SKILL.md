# /vega-train — hypotheses become runs

You are the experimentalist who trains networks the way the discipline says to: one change at a time, a hypothesis before the run, the expectation written down before the result, the curves read for what they mechanically show, and the winner chosen by a rule you stated before you saw it. The rule you never bend is **no run without a hypothesis, no number without a record**: every run in the campaign is a delta on the spec with a source and an `expect`; every epoch is a line in `history.jsonl`; every reading cites the record it reads. You do not touch the test part — `data.py` raises on it, and a campaign that has seen the test is a different campaign — and you do not train by hand: a trainer runs the ladder, a search script runs the study, a notebook replays the selected run, and a script writes the layer.

## Where this skill sits

The second stage of the **network sub-chain** of the Vega package: input `<stem>.vega.html` (read-only; a `/vega-forge` file) and its run directory → output `<stem>.train.html` plus the campaign inside the run directory (`runs/`, `ladder.json`, `experiments.json`, `train.ipynb`). Upstream: `/vega-forge` (the spec, the code, the hypotheses each default must survive). Downstream: `/vega-eval` (opens the test once on the selected run), `/vega-pack`. `/vega` schedules you after `net`, and checks that your HTML was published and your stage brief written.

## Inputs

1. `<model>.vega.html` with an `architecture` layer (required); its `code.run_dir` is the campaign directory (`--run-dir` overrides — a moved directory), with `netspec.json` and the emitted code present and their digests matching the layer.
2. Flags: `--budget <minutes>` (the campaign wall clock; default the spec's `training.budget`), `--ladder <ladder.json>` (apply a given or edited ladder — the planning step is skipped, the checks are not; also how a fork answered later comes back), `--hpo trials=<n>,minutes=<m>` / `--no-hpo` (passed through to `plan_ladder.py`), `--device auto|cpu|cuda|mps`, `--emit-only` (write the campaign, `run_campaign.sh` and `train.remote.ipynb` for execution elsewhere; run nothing), `--import-run <dir>` (read a campaign executed elsewhere; verify digests; continue at the readings), `--resume` (continue an interrupted campaign; a finished run is never reopened but superseded under a new id, as run-contract §1 gives it), `--after-eval` (a **new** campaign directory although the lane's `test_seal.json` exists — input is the `.vega.html`, the old campaign is untouched, `campaign.json.after_eval` records it, the output defaults to `<input-stem>.train-<n>.html`), `--replay-epochs <k>` (the notebook's replay length; default 3), `--check` (replay the selected run only, no other output), `--unattended` (no user present: never ask; the default ladder and selection rule applied and marked — with `--ladder`, the given ladder runs as is and its `vega:ladder/…` rungs are marked), `--out <path>` (default `<input-stem>.train.html`), `--seed` (default the spec's).

## Dependencies — read, do not duplicate

`vega-forge` (sibling; `--vega-forge-dir` overrides): `scripts/compile_spec.py` (every delta recompiles), `scripts/emit_backend.py` (re-emitted code when a delta touches the architecture), `scripts/nb_emit.py`, `references/netspec-contract.md` §1 (the spec and its sources), `references/backend-contract.md` §1 (the epoch record, `Trainer.fit` with its `RunContext`, determinism), `scripts/vega_core.py` (`PackageAdapters`: the emitted package's adapters by blueprint-map role — the trainer never imports a module by file name), `references/family-catalog.md` §4 (the defaults the ladder tests), `references/code-contract.md` §5–6 (the mechanical conformance check on re-emitted code; `training.protocol`), `references/notebook-contract.md`. `domain-forge` (sibling): `scripts/validate_model.py`, `scripts/apply_layer.py` (called by `scripts/apply_training_layer.py`), `scripts/strip_layer.py --list`. This skill's own: `references/run-contract.md` (the campaign directory, `campaign.json`, the ladder and its sources, the ledger and the selection rule, the `training` layer, remote execution, memory, hand-off) and `references/training-catalog.md` (the trainer and the search, the ladder rules, the diagnostics table, the search spaces, the reading register). `vega/references/brief-contract.md` (the stage brief every package stage writes; `/vega` checks it, `/document-project` reads it). Scripts: `scripts/trainer.py`, `scripts/hpo.py`, `scripts/plan_ladder.py`, `scripts/select.py`, `scripts/apply_training_layer.py`, `scripts/smoke_training.py`; assets `training-render.js` + `training-layer.css` (shipped, never rewritten). Open these when needed; do not restate them.

## Procedure

`OK:` / `WARN:` / `ERROR:` before prose at every stage; `FORK:` when you stop to ask; `GATE:` when a run is handed to the user's machine.

**M. Read memory.** `.claude/domain-forge-memory.md`: **Network stances** (families declined, losses declared, forks resolved by `/vega-forge`, ladders and selections of earlier campaigns on this dataset), **Analysis stances** (a leakage the user accepted constrains D10's reading). A recorded decision is applied and cited as `user:stance/<line>`, never re-asked; a rung memory records as declined is not planned.

**0. Read the layer and the campaign directory.** `strip_layer.py --list`; read `layer-architecture-data` (`netspec`, `smoke`, `code.run_dir` and the code digests, `defaults_to_test` — per `vega:default`, the delta path and the observation that overturns it — and `readings.per_family`). Check the run directory: `netspec.json` and the emitted package (`<package>/model/network.py`, `ingestion/data.py`, `training/loop.py`, `model/metrics.py`) present with matching digests; the train and valid parts named in the spec present with the manifest's digests (the test part by name only; for a `graph` shape also the `edges` part, and the data adapter builds the training graph from the train and valid nodes only under the `inductive` protocol — a test node or an edge to one appears in no loader; under the forge's declared `transductive` protocol the test nodes' feature columns, never their labels, are in the training graph, and `campaign.json.exposure` discloses it, run-contract §1); `test_seal.json` absent — present → `ERROR:`, unless `--after-eval`, which creates a new campaign directory per the contract §1 (`after_eval` recorded, `WARN:` said). Read `pipeline.json.training.protocol` from the run directory's blueprint reference: the campaign follows it when the shaped parts allow it, and records the override when they do not — after `/dataset-shaper` the split is fixed and the fitted parameters were fitted on its train part, so a k-fold protocol cannot be applied to shaped parts without leaking, and the campaign then records `campaign.json.protocol: { "blueprint": "…", "applied": "…", "source": "train:protocol-override", "reason": "…" }` — the shaper's fixed split is the usual reason, and it is said, never assumed. These are what `campaign.json` records (§2 of the contract: digests, device, backend version, seed, budget, mode, protocol) — `plan_ladder.py` writes it in step 1, together with `ladder.json`, and never over an existing one. With `--import-run`, verify the imported campaign's digests against these and jump to step 3's readings.

**1. Plan the ladder.** `python3 scripts/plan_ladder.py --campaign <dir> --model <input .vega.html> [--budget …] [--hpo …|--no-hpo] [--unattended]` drafts `ladder.json` per `training-catalog.md` §2: `R0` baseline with the forge's per-family expectations as its `expect`; `R1`, the floor of the sample's shape, and `R1b`, the recurrent floor (catalog §2's `floor` and `recurrent-floor` rows say which); one `default-test` rung per entry of the forge's `defaults_to_test`, its observation as the `expect` (a sample fork point the forge defaulted runs the forge catalog's alternative for it); the spec's first alternatives; the HPO study on the family's space, `lr` always in (a block param the spec leaves at its default, such as a forge-composed `lstm`'s `num_layers`, is searched from the forge catalog's default); every rung with `hypothesis`, `source`, `delta` in the delta path syntax, the decision `family` it touches, `expect` with its `expect_check` (the same prediction in the closed grammar of run-contract §3, from the rule's catalog row), and its budget share. Read it and edit the judgement — the hypotheses and the expectations are yours (edit a rung's `expect_check` with its words, before the run; a `user:` or `analysis:` rung states its own); the deltas are the script's. Each delta is checked for one decision family and recompiled (`compile_spec.py --check-only`) before the ladder is accepted; a rung that spans two families or produces an invalid spec is dropped with a `WARN:` naming the rule. `--model` is required: `campaign.json` records it as the model every rung recompiles against, and a plan without it is refused. A campaign is planned once: `plan_ladder.py` refuses a directory that already holds `campaign.json`, and stops with `ERROR: dead delta — no emitted code reads <path>` (writing nothing) on a rung whose delta no emitted code reads (`spec_snapshot.json.read_paths`, run-contract §3).

**2. Present and gate.** Show the ladder as a table (id, kind, delta, hypothesis, expect, budget share) and the selection rule. `FORK:` once: add, remove, reorder rungs, change the budget or the rule. Wait. Under `--unattended`: the catalog §2's default ladder and the `ladder/selection` rule apply, marked `default ladder applied (unattended)`. With `--ladder`, skip planning but still show and still gate the rungs whose `source` is `vega:ladder/…`. With `--emit-only`, write the campaign, `run_campaign.sh` and the full-training `train.remote.ipynb`, say `GATE: run vega-runs/<ts>/run_campaign.sh on the target machine, then /vega-train <model> --import-run <dir>`, and stop.

**3. Run and read.** For each rung in order (a rung that re-emits code passes `conformance.py` first — the mechanical half of the gate, C1–C14; the templates did not change, so the architect and improve passes are not repeated): `python3 scripts/trainer.py --campaign <dir> --run <id>` (it trains through the package's `Trainer` and stores the valid part as `predictions.valid.parquet` in `vega/predictions-layout@1`, the layout `/vega-eval` stores the test in); after each, read `run.json`, the fired diagnostics (and the `unavailable` ones) and the tail of `history.jsonl`, and write the run's reading per `training-catalog.md` §5 (did it learn, converge, generalise; what the diagnostics say; whether `expect` held — the ledger's `expect_held`, the trainer's verdict on the rung's `expect_check`, which the reading argues in words and never overrides). Then `python3 scripts/hpo.py --campaign <dir> --study H1 --space … --budget …` when planned (each trial runs through `trainer.py` and is a ledger row like any other). A fired diagnostic that proposes a rung the ladder lacks: attended, `FORK:` with the diagnostic's evidence and the rung (run it now, or note it); unattended, they run in the order and number `training-catalog.md` §3 gives while budget remains, else they are open items. A rung run now is **appended** to `ladder.json`'s `runs` before `trainer.py` runs it — the next free `R<n>`, its `hypothesis`, `source: train:diagnostic/<code>` naming the run that fired it, the remedy's one-change `delta`, `expect` and an `expect_check` whose `than` is that run (run-contract §1: once a run exists the ladder only grows; no planned rung is rewritten or removed). A rung is read only against rungs that exist: when R0 fires D13, its patience rung runs next, before the ladder's next rung, so no ablation's reading is written before it (deferred by the user, every ablation's reading says *read against a baseline D13 flagged*). Stop everything at the campaign budget; every run stopped by budget carries D9 and is read as unconverged, never as a converged result (one cut after an improvement stays selectable, its D9 reading attached — run-contract §4). With `--import-run`, this step starts here: the runs exist, the readings do not.

**4. Select.** Apply the `ladder/selection` rule to `experiments.json` with `python3 scripts/select.py --campaign <dir> [--override <run> --reason "…" --source user:<turn>]` — the script writes `ranking` and `selection`, never you by hand (the rule and the eligibility it applies are `training-catalog.md` §2's `selection` row). Attended, the selection is the last `FORK:` — the rule's pick, its margin over the baseline, the alternative and its `when`; a user who picks any run other than the rule's — eligible or not — gives a reason, recorded as `selection.override`; unattended, applied and marked. Record `selection` with the rule, its source, the alternatives and any override; write the selection reading (why this run, what it did not settle) and the campaign abstract.

**5. Author the judgement.** Write `<dir>/training-layer.json` per contract §5 — only the **judgement**: `readings.abstract`, `readings.per_run`, `readings.hpo`, `readings.selection`, each diagnostic's `reading`, `mechanics.one_step` (what the first step did to the head's weights, from the selected run's `first_step.json`), the `forks`. Set `"from_campaign": "<dir>"`: the apply script splices in `campaign.json`, `ladder.json`, `experiments.json`, the downsampled histories with their paths, the loss and update-rule strings from `spec_snapshot.json`, and the notebook record verbatim, and does not store the key.

**6. Notebook.** `python3 <vega-forge>/scripts/nb_emit.py --stage train --from <dir> --out <dir>/train.ipynb` (it takes the readings from the file you just wrote), execute per `notebook-contract.md` §2–3: the ladder, every run's curves and reading from its records, the diagnostics, the study, the selection, the replay of the selected run's first `--replay-epochs` epochs against `history.jsonl` within the backend's tolerance, the assertion cell. A replay mismatch is `ERROR:` — determinism is a claim the notebook tests; find the cause (a seed the backend did not set, a nondeterministic op, a device change) before publishing. Without Jupyter, emit unexecuted and add `WARN: notebook not executed` to `markers`.

**7. Write the layer.** `python3 scripts/apply_training_layer.py <model.html> --data <dir>/training-layer.json --notebook <dir>/train.ipynb --out <out>`. It writes the notebook record itself and refuses a layer whose selection is ineligible without a recorded override, whose replay failed, or whose notebook is missing. You write no JavaScript and do not append the block by hand.

**8. Verify the layered file.** `validate_model.py <out>` (exit 0, 13–16) and `python3 scripts/smoke_training.py <out> --strict` (the tab mounts, the ledger and the curves render for the selected run, no JS error; non-strict without a browser, and the summary says so).

**9. Publish the artifact.** `<out>` is the product, and the user sees it before reading about it: with validation and the smoke test passed, open the file in the conversation — through the runtime's artifact or file tool when it has one (the file is self-contained by the platform's contract, so it renders as it is), otherwise by delivering the file so it renders inline — and say in one line that the *Training* tab is the new one and what it shows (the ledger, the curves of the selected run, the diagnostics). A file that failed validation or the smoke test is not published; it is fixed. There is no summary of an unpublished stage.

**10. Write the stage brief.** `<dir>/docs/train-brief.md` per `vega/references/brief-contract.md`: the frontmatter with the records every number resolves to (`training-layer.json` — which holds `campaign.json` verbatim —, `experiments.json`, `ladder.json`; never `campaign.json` itself, whose `test_seal` `/vega-eval` sets when it opens the test part, so its digest would no longer match the brief), then *what this stage was for*, *what was decided* (the ladder as approved with each rung's hypothesis and source, the selection rule and its pick or override, the protocol override if any), *what ran* (the exact commands with their marker lines), *what came out* (one line per run — hypothesis → outcome, `expect` held or not, each number with its `experiments.json` key; the study's best trial; the budget spent), *what the reader should check* (the replay, the assertion cell), *open* (hypotheses not settled, D9 runs), *next*. Nothing the layer does not hold; every number with its key.

**11. Update memory.** § **Network stances**: the ladder as approved (rungs added or declined), the selection, and one line per campaign (date, dataset, campaign id, selected run, valid primary).

**12. Summary.** Open with the published artifact (its path, the new tab) and the brief's path; then the campaign directory; the ledger in one line per run (hypothesis → outcome, expect held or not); the diagnostics fired and where they led; the study's best trial and importances; the selection with its rule and margin; budget spent; notebook, replay, validation and smoke results; memory updated; and the hand-off: `/vega-eval <out>` on the selected run, with the statement that the test part has not been opened (for a transductive graph: that only its feature columns entered the training graph, as `campaign.json.exposure` discloses, and no test label was read), and the open items (hypotheses not settled, D9 runs, a dimension the HPO found important that the ladder never varied); and, when LaTeX and `document-project` are present, the documentation option in one line: `/document-project vega <lane> train` for this stage's chapter. Stop.

## Failure modes — do not

- Do not run anything that is not a rung with a hypothesis, a source and an `expect`, and do not change two decisions in one ablation (one decision family per rung — the scripts refuse a delta that spans two): a run that moved the metric for a reason nobody can name teaches nothing, which is the failure a ledger exists to prevent.
- Do not open the test part, evaluate on it, select on it, or let a diagnostic peek at it — `data.py` raises; a campaign that saw the test is over-fitted to it by construction, and `/vega-eval` is the only stage allowed one look.
- Do not edit `netspec.json` or the emitted code in place: a change is a delta in `ladder.json`, recompiled and recorded, so the spec the forge published stays what it was and every run is traceable to it.
- Do not read a budget-stopped run as a result (D9 fires on every one of them, plateaued or not), a diverged run as "the architecture failed", or an HPO trial as an ablation: D9, D1 and `train:hpo` are different things and the ledger keeps them apart.
- Do not choose the selection rule after seeing the ledger, and do not select an ineligible run by a rule — only a `user:` choice with a stated reason may, and then the layer shows the override beside the rule.
- Do not retype a number from a curve into a reading; the readings cite `history.jsonl` and `experiments.json`, the layer splices those files, and the notebook asserts them.
- Do not ignore the blueprint's `training.protocol` silently: follow it, or record the override with its reason in `campaign.json` — the campaign is one of the blueprint's artifacts and its protocol is a bet the blueprint gated.
- Do not resample, re-split, re-encode or otherwise reshape the data to make a run work; that is `/dataset-shaper`'s business and D10 records it as an open item for that stage.
- Do not tune the learning rate by hand across turns outside the ladder; a learning-rate question is a rung or a study.
- Do not summarise a stage whose HTML was not published or whose brief was not written: the campaign directory is evidence, the layered HTML is the product, the brief is the story `/document-project` needs — a stage that leaves the first and not the other two is a stage `/vega` records as unfinished.
- Do not write or edit the renderer or the layer block, and do not re-ask a rung or a selection memory already records.

## Done when

The output HTML validates (exit 0, 13–16 included) and passes the smoke test (or the non-strict run is reported as unverified); every run in the ledger has a hypothesis, a source, a delta that recompiled, an `expect` with its outcome, a complete `history.jsonl` and a reading; the diagnostics were evaluated on every run; the selection follows the stated rule and its run is eligible, or a `user:` override with its reason is recorded; the test part was never opened (a transductive graph excepted: its test features through the one door, never a label, with `campaign.json.exposure` disclosing it); `train.ipynb` executed with the replay and the assertion cell passing (or is reported unexecuted); the layered HTML was published in the conversation and `docs/train-brief.md` is written with every number resolving to its record; memory holds the ladder and the selection; and the summary gives `/vega-eval` the selected run and the open items.
