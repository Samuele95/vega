# vega-train catalog — the trainer, the ladder rules, the diagnostics, the search spaces

## 1. The trainer (`scripts/trainer.py`) and the search (`scripts/hpo.py`)

`python3 scripts/trainer.py --campaign <dir> --run <id>` reads `ladder.json`, applies the run's `delta` to `netspec.json`, recompiles (`compile_spec.py --check-only`; refuses on failure), re-emits the code when the delta touches the architecture (through the same package templates into `runs/<id>/<package>/`, with the campaign root as `--campaign-root` so a custom block's `code_ref` still resolves, and `conformance.py` on the result), and opens the package the way every stage does: `vega_core.PackageAdapters.load` resolves each port's adapter by its blueprint-map role — `Network.build`, the `ShapedParts` DataSource (which raises on the test part), the `Trainer`, the `ModelRegistry` store and, when the blueprint drew one, the `Evaluator`. It calls `Trainer(store).fit(model, spec, data, callbacks, run=RunContext(budget_min, checkpoint_dir, grad_sample_every))` (the Trainer given the ModelStore its best checkpoint is written through) with a callback that appends each epoch record (`EpochRecord.as_dict()`) to `history.jsonl` and each sampled step's pre-clip norm to `grad_stats.jsonl`. It stops on early stopping, on `max_epochs`, on the run's share of the campaign budget, or on a `nan` record (then `stopped_by: divergence`), writes `run.json`, `predictions.valid.parquet` from `best.pt`, the SVG figures, and appends the run's row to `experiments.json`. `predictions.valid.parquet` is the valid part in `vega/predictions-layout@1`, the layout `/vega-eval` stores for the test part (`vega-eval/references/eval-contract.md` §2 owns it): the Evaluator's `ScoredPart`, its metadata beside the layout's own keys naming `vega.part` and `vega.score_source`; the rows a window cannot score are counted in `run.json.predictions_unscored`, never given a fabricated answer. A package without an Evaluator port is scored through `Trainer.predict`, and the metadata says `vega.score_source: readout` where that reading keeps less than the whole head. `--resume` follows `run-contract.md` §1 (a `running` run continues under its own id; a finished one is superseded under a new id, never reopened). A delta that moves a block param the spec leaves unstated (an HPO trial on a forge-composed `lstm`'s `num_layers`) is checked and applied from the value the block is built with — the older name it still reads, else the forge catalog's default — which the resolved spec then states. `run.json.device` is the device the package's own Trainer picks (`PackageAdapters.device_for(spec)`: the Trainer module's `optim.device_for`). `--replay <id> --epochs k` re-runs the first `k` epochs from the spec as the run resolved it (`max_epochs` included — the schedule is a function of it; the replay stops itself after `k` records and writes no checkpoint) and compares records within the backend's determinism tolerance (the notebook's replay cell; the skill's `--check` flag runs the same replay on the selected run without emitting anything else). A diagnostic whose condition needs a record field the backend wrote as `null` is recorded in the run's `unavailable` list, never guessed.

`python3 scripts/hpo.py --campaign <dir> --study <id> --space <space.json> --budget trials=20,minutes=8` runs a study whose trials are runs `H<id>-<n>` in the same ledger: Optuna (TPE sampler, median pruner on the primary valid metric) when installed, otherwise random search with the same interface and `WARN: optuna absent; random search`. `space.json` declares each dimension as `{path, kind: float|int|categorical, range|choices, log}` on spec paths in the delta path syntax of `run-contract.md` §3; `importance.json` is fANOVA (Optuna) or the variance of the metric across the dimension's quantiles (fallback), and the layer shows which. Pruned trials stay in the ledger as `status: pruned` with their partial history.

Budget arithmetic: the campaign's `wall_clock_min` is split as the ladder declares (`budget` per run or per study; unset runs share what is left equally); a run is stopped at the epoch boundary that exceeds its share and recorded `stopped_by: budget` — D9 fires on every such run, and its reading says whether the run had plateaued or was still improving. On `--device cuda` the trainer records the GPU and memory; determinism tolerance comes from the backend.

## 2. Ladder rules — what the skill plans on its own

The default ladder is short and every rung has a reason. Rung ids: `R0` the baseline, `R1` the floor, `R1b` the recurrent floor — each rule's id whether or not its rung was planned, so a dropped floor never lends its id to another rung — then `R2`, `R3`, … in ladder order. `vega:ladder/<rule>` is the source of a rung the skill added; a rung the spec's own `alternatives` suggest cites `netspec:<path>`; a rung a diagnostic fired cites `train:diagnostic/<code>`.

| rule | rung | hypothesis it tests | expect |
|---|---|---|---|
| `baseline` | R0: the spec as engineered | none — it is what every other run is read against | the spec's `readings.per_family` said what the first run must show; that is R0's `expect` |
| `floor` | the `linear` family on the same features (supervised), or `pca-floor` (reconstruction, anomaly), per sample shape: on a window `linear` reads the window through a `flatten` inserted before the head, at graph level through `graph_pool(mean)`, at node level it is structure-blind (each node's own features, no edge read); `pca-floor` is the linear autoencoder of the forge's composition, the features through `dense(z, none)` inserted before the task's head, z the spec's own bottleneck (the narrowest top-level `dense`, or a `reparameterize` block's z) or else the geometry layer's `dims_95`; a spec whose family already is the floor gets none, nor does a node-level sample under neighbour sampling (the floor has no convolution to draw a fan-out for), nor a PCA floor with no z to read — each dropped with a `WARN:` saying why. Its id is always `R1` | the non-linear structure the analysis or the posture claims is real (at node level: the structure the edges carry) | the floor clearly below the baseline; if not, the network has not earned its parameters and the summary says so |
| `recurrent-floor` | `R1b`, for the families the forge catalog's `rnn` row is the ablation floor of (`families/rnn.ablation_floor_for`: `gru`, `lstm`, `bi-lstm`, `bi-gru`, `lstm-attention`, `gru-attention` — the forge catalog's list, held equal to it by `scripts/tests/test_catalog_sync.py`): the recurrent block swapped to `rnn` with the same `hidden` and `num_layers`, `return: last`, `bidirectional: false`, no `attention_pool` (every block the `rnn` composition does not hold removed), the head kept | the gated cell buys long-range memory: `rnn` must sit below the baseline | `R1b` below `R0` on valid primary; if not, the gate buys nothing on windows of this length and the summary says so |
| `default-test` | one rung per entry of the forge's `defaults_to_test` (attended: all of them; unattended: at most four, ranked dropout, weight decay, schedule, normalisation by the entry's path, every other entry — a `data_contract/sample/<point>` one included — after those in the forge's order, and the first four kept); a `data_contract/sample/<point>` entry — a sample fork point the forge defaulted — runs the forge catalog's alternative for that point (the forge catalog's alternative for that fork point) | each default, tested by its removal or its first alternative | the removal hurts on valid or widens the gap — the entry's own observation |
| `spec-alternative` | the first alternative of the family, the optimizer, the loss | the spec's own `alternatives[0]` | stated by the alternative's `when` |
| `capacity` | width ×2 and ÷2, or depth ±1 | the catalog's sizing rule is near the right region | the curve of valid metric against capacity peaks near the baseline |
| `hpo` | one study on the family's §4 space, `lr` always included (the reading afterwards says which of those dimensions the rungs above had already moved) | the dimensions interact | best trial ≥ baseline |
| `diagnostic` | a rung a diagnostic proposed (§3): the *first* remedy in its row, unless the user picks another | the diagnostic's reading | the remedy's predicted effect on the record that fired it (D3 → the gap shrinks; D5 → the std falls) |
| `selection` | not a rung: the selection rule — best valid primary in the direction of `metrics.selection.mode`, ties → fewer parameters, ineligible runs excluded (D1, D2, D9 before first improvement, pruned trials) | — | the alternative is the user's pick with a reason, recorded as `selection.override` |

Each rule's `expect` also has its machine form, the `expect_check` `plan_ladder.py` writes on the rung (`scripts/catalog.json` `ladder_rules.<rule>.expect_check`, in the grammar of `run-contract.md` §3): `baseline` learns; `floor` is worse than R0 on `valid.primary` by more than 5 % of R0's value; `recurrent-floor` is worse than R0; `default-test` is worse than R0 on `valid.primary` or on `gap.loss`; `spec-alternative` and `capacity` are not better than R0; `hpo`'s best trial is not worse than R0; `diagnostic` betters the run that fired it (the catalog's default names R0; the skill sets `than` to that run). The trainer judges the check into the ledger row's `expect_held` (`run-contract.md` §4); `scripts/tests/test_catalog_sync.py` fails when a rule's check does not parse.

Attended, the planned ladder is one `FORK:` (add, remove, reorder rungs; the budget); unattended, rules `baseline`, `floor` (`linear` for a supervised task, `pca-floor` for reconstruction and anomaly), `recurrent-floor` (the recurrent families only), `default-test` as its row says (none applicable → the rule is skipped and said so) and `hpo` (12 trials on the family's §4 space, `lr` always in) run within the budget, in that order, and the layer marks `default ladder applied (unattended)`. `--ladder` with `--unattended`: the given ladder runs as is, its `vega:ladder/…` rungs marked `default ladder applied (unattended)` — unattended never asks. A campaign under a budget that cannot afford the baseline to converge stops after the baseline and says so.

## 3. Diagnostics — symptom → reading → rung

The trainer evaluates these on every finished run from `history.jsonl` and `grad_stats.jsonl`; each fires with its evidence; the skill writes the reading; a fired diagnostic may propose a rung (attended: offered in the ladder fork or as a follow-up `FORK:`; unattended: the first remedies of the first two fired diagnostics **that propose a rung** run if the budget allows — D13's first, when it fired on R0, then the others in the order the runs ended and, within a run, in code order D1…D13 (a diagnostic whose remedy is not a rung — D9's resume, D10's and D11's open items — takes no slot); the unrun ones are listed as open, and an ablation read against a baseline D13 flagged is marked so in either mode). Conditions joined by a comma are conjunctions. "Primary rises / falls / improves" is read in the direction of `metrics.selection.mode`; loss thresholds are relative to the run's best valid loss so they hold for a regression loss in any unit.

| code | symptom (mechanical) | reading | rung it proposes |
|---|---|---|---|
| D1 divergence | a `nan` record, or train loss > 10× its epoch-1 value | the learning rate is too high, an input is unscaled, or clipping is off | lr ÷ 10; `grad_clip` on; check the manifest's `scale` step |
| D2 not learning | valid primary within 1 % of its epoch-1 value after 20 % of epochs, **and** `update_ratio` < 1e-5 on every block — the update ratios carry the finding (the weights do not move), so it does not depend on the primary's scale or sign; the 1 % band only confirms that the primary did not move either, and an epoch-1 primary of exactly 0 has no band, so D2 is then not fired and the run's reading cites the update ratios itself | the learning rate is too low, activations are dead, or the head is wrong | lr × 10; activation `gelu`/`leaky_relu`; the compiler's head check |
| D3 overfitting | after the best epoch, valid loss rises ≥ 5 % of its best value over 10 epochs while train loss falls | capacity exceeds the rows; regularisation too weak | dropout +0.2; weight decay ×10; width ÷2; earlier stop |
| D4 underfitting | train loss changed < 1 % over the last 20 % of epochs, train primary no better than the floor's valid primary (by ≥ 5 % of the floor's value, in the mode's direction; before the floor ran, D4 is `unavailable` for that run, and the run's reading compares it with the floor once the floor exists), and the train/valid loss gap < 5 % of the valid loss | capacity or epochs insufficient, or features carry little signal (cf. `analysis:importance`) | width ×2 / depth +1; more epochs; remove dropout |
| D5 thrashing | valid primary oscillates with std over the last 10 epochs > 5 % of its range so far, and `update_ratio` > 1e-2 on any block | lr too high late, batch too small | lr ÷ 3; batch ×2; schedule `plateau` when the spec has none |
| D6 vanishing gradients | per-block gradient norm of the first block < 1e-3 × the head's for 5 epochs | depth without residuals or normalisation, saturating activations | `residual`, `layernorm`; `gelu` |
| D7 exploding gradients | pre-clip global norm > 100 on ≥ 1 % of steps — absolute on purpose, and the same whatever the spec's `grad_clip`: it reads the gradient **before** the clip, which is exactly what a clip hides (a spec clipping at 1, at 10 or not at all takes the same exploding step direction, only rescaled), and 100 is two orders of magnitude past the catalog's bound (`defaults/grad_clip`, 1.0) — a norm that large is the explosion D1 grows out of, not a scale effect of the loss's unit | as D1 without divergence yet | clipping tighter; lr ÷ 3 |
| D8 stale early stop | best epoch < 20 % of epochs, then no improvement | the metric peaked early: lr too high after warmup, or the metric is noisy on a small valid part | patience ×2; lr ÷ 3; `min_delta` lower (the valid size is noted in the reading, not a rung) |
| D9 budget cut | `stopped_by: budget` before early stopping (always fires on such a run; its evidence says whether valid primary was still improving over the last 5 epochs or had plateaued) | the run did not converge, or converged by accident of the budget; the campaign's budget, not the spec, ended it — never read as a result | resume with `--resume` when budget is added; the summary flags it |
| D10 train/valid disagreement | over the first 20 % of epochs (≥ 5), train primary improves by ≥ 2 % of its range while valid primary worsens by ≥ 2 % of its range | leakage in a feature the shaper kept, or a valid part from a different distribution (cf. `analysis:modules/drift`) | none (not a rung): re-check the shaper's leakage set and the split — recorded as an open item for `/dataset-shaper` |
| D11 dead embedding | an embedding's gradient norm is 0 for 3 epochs | the nominal never varies in the batch order, or the cardinality is wrong | none (not a rung): `data_contract.features[].cardinality` is re-checked against the manifest and the finding goes to the forge as an open item |
| D13 stopped before the schedule decayed | early stopping fired while the learning rate was still ≥ 80 % of its peak **and** the valid primary was still improving beyond its noise: over the last `patience` epochs its mean epoch-to-epoch change, signed in the direction of `metrics.selection.mode` (a rise for `max`, a fall for `min`), exceeds that change's standard error (the sd of the differences over √n) | the run was read as converged while it was still learning through noise — with the default patience every ablation is then compared at an under-trained baseline (measured: patience 30 gained +0.048 where patience 10 stopped at epoch 22–58 of 200) | `early_stopping.patience` × 3 (source `train:diagnostic/D13`), run **before** the ladder's ablations are read — a ladder whose R0 fired D13 is re-based on the patience rung in its **reading**, and the summary says so: no delta is rewritten to follow it (the trainer applies every rung's one-change delta to `netspec.json`, and a delta carrying the patience too would be two changes), so each ablation is still compared with R0, its like-for-like baseline, and its reading says R0 was flagged by D13 and what the patience rung showed; the selection reads the patience rung, not R0, as the spec's own result; unattended, D13's patience rung runs first among the diagnostic rungs whenever R0 fired it; attended, a user who defers the rung leaves every ablation's reading marked *read against a baseline D13 flagged*, and the selection's reading says so |
| D12 calibration drift | over the last 10 epochs valid log-loss rises ≥ 5 % of its best value while valid ROC-AUC rises ≥ 0.005 (classification tasks only) | scores are getting sharper without getting better; the class weight over-corrects | `pos_weight` ÷ 2; label smoothing (and `/vega-eval`'s calibration reading will say the rest) |

A diagnostic is a *mechanical* condition on the records; its reading is the skill's; the rung is a proposal. Nothing here overrides a stance the user recorded.

## 4. Search spaces per family (defaults for `hpo`)

| family | dimensions (spec paths), each with its range | notes |
|---|---|---|
| `mlp-*` | `optimizer/params/lr` (log 1e-4 … 1e-2), `blocks/<first dense id>/params/units` (int 32 … 512, log; the emitter keeps the residual inner widths equal to it), `regularization[kind=dropout]/value` (0 … 0.5), `regularization[kind=weight_decay]/value` (log 1e-6 … 1e-2), `blocks/<residual id>/params/repeat` (1 … 4) | |
| `ft-transformer` | `optimizer/params/lr` (log 1e-5 … 1e-3), `blocks/<tokenizer id>/params/d` {32, 64, 128}, `blocks/<encoder id>/params/layers` (1 … 4), `regularization[kind=dropout]/value` (0 … 0.3) | |
| `cnn1d` / `gru` / `lstm` | `optimizer/params/lr` (log 1e-4 … 1e-2), `blocks/<conv or rnn id>/params/channels` or `/hidden` {32, 64, 128}, `/kernel` {3, 5, 7} or `/num_layers` (1 … 2), `regularization[kind=dropout]/value` (0 … 0.5) | |
| `rnn`, `bi-lstm`, `bi-gru`, `lstm-attention`, `gru-attention` | `optimizer/params/lr` (log 1e-4 … 1e-2), `blocks/<rnn id>/params/hidden` {32, 64, 128}, `blocks/<rnn id>/params/num_layers` (1 … 2), `regularization[kind=dropout]/value` (0 … 0.5); `*-attention` adds `blocks/<attention_pool id>/params/hidden` {32, 64} | |
| `gcn`, `graphsage`, `gat`, `gin` | `optimizer/params/lr` (log 1e-3 … 5e-2), `blocks/<first conv id>/params/out` {32, 64, 128} (the first convolution's width; the later ones keep theirs), `regularization[kind=dropout]/value` (0 … 0.7), `regularization[kind=weight_decay]/value` (log 1e-6 … 1e-3); `gat` adds `blocks/<first gat id>/params/heads` {4, 8}; a spec with an `edge_dropout` block adds its `p` (0 … 0.3; an optional dimension, searched only when the block is there) | |
| `autoencoder` / `vae` | `optimizer/params/lr` (log 1e-4 … 1e-2), `blocks/<bottleneck id>/params/units` (int `dims_95`/2 … 2·`dims_95`), encoder depth (1 … 3, as `repeat` of the encoder's sequential), `loss/params/beta` (0.1 … 4, log; vae) | |

`plan_ladder.py` resolves the `<… id>` placeholders from the spec's blocks by type (`<rnn id>`: the first `gru`, else `lstm`, else `rnn`; `<first conv id>`: the first `gcn_conv`, `sage_conv`, `gat_conv` or `gin_conv`); a block param the spec leaves unstated is searched from the value the block is built with — the older name it still reads (`layers` for `num_layers`), else the forge catalog's `blocks[<type>].defaults` — and `space.json` records where that `current` came from (`current_from`), while the trainer writes it into the trial's resolved spec so the delta has a `from` to check; the autoencoder ranges written in `dims_95` resolve on the geometry layer's `space.dims_95` (on 8 when the model carries none); a dimension whose block the spec lacks is dropped with a `WARN:` — an optional one silently, listed under `not_applicable` in `space.json`; a family without a row here gets `lr` and every `regularization[kind=…]/value` the spec carries, and the summary says the space was generic.

The attended draft's default budget is 20 trials (12 unattended) or the remainder of the campaign's wall clock, whichever ends first; `lr` is always searched because every other dimension's effect depends on it.

## 5. Reading register

`mechanics.one_step` of the layer is read from the selected run's `first_step.json` (the head's ‖g‖, ‖Δθ‖ and ratio at epoch 1 step 1) — never computed by hand.

A run's reading answers, in that order: did it learn (D2), did it converge (D9, best epoch vs epochs), did it generalise (gap, D3), what the diagnostics say, whether `expect` held and what that settles about the spec. The campaign's abstract says what the ladder established about each decision family, which run was selected and by which rule, and what remains open — with the numbers from the ledger, never retyped from memory.
