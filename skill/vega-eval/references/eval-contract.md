# vega-eval contract — the seal, the protocol, the metrics, the baselines, the `evaluation` layer

`/vega-eval` answers one question with one look: **how good is the selected network on data it has never seen, and did it earn its cost against honest baselines?** The test part is opened once, by the evaluator, under a stamped seal; every metric travels with a confidence interval; every comparison is against a baseline trained under the same protocol on the same features; every slice is one the chain already named. The evaluation directory is the truth: the evaluator writes the predictions and the metrics, the notebook recomputes the metrics from the stored predictions (never from the network again), the layer shows them, and `/vega-pack` checks its bundle against them.

## 1. The seal (`test_seal.json`)

Written by the evaluator into the campaign directory (beside `campaign.json`, whose `test_seal` it sets to this path) **before** the first byte of the test part is read — the path comes from the shaper's manifest (`outputs.files.test`), the digest is computed by the evaluator right after the seal exists and compared with the manifest's:

```json
{ "schema": "vega/test-seal@1", "campaign": "vega-runs/2026-09-05T11-03Z/", "run": "H1-14",
  "test": { "path": "shaped/orders.test.parquet", "digest": "sha256:…", "rows": 120, "digest_matches_manifest": true },
  "opened_at": "2026-09-05T12:40:11Z", "exposures": 1,
  "graph": { "protocol": "inductive | transductive", "edges_into_test": 0, "features_seen_in_training": false },   ← only for a `graph` sample shape; under `transductive` the last field is true and the layer shows the disclosed feature exposure
  "after_eval": { "previous_campaign": "vega-runs/2026-09-01T09-12Z/", "exposures": 1 },   ← only in a campaign `/vega-train --after-eval` started: the earlier looks, counted in `exposures`
  "history": [ { "at": "2026-09-05T12:40:11Z", "run": "H1-14", "reason": "first evaluation", "gate": "user | unattended" } ],
  "token": "<random token the evaluator passes to data.load_sealed_part>" }
```

`graph` is written once the package's `ShapedParts.exposure(spec)` has read it (after the seal, before the test part is opened) and is repeated in `metrics.json.graph`. `data.py` (the emitted code) opens the test part only through `load_sealed_part(spec, token)` with the token this file holds; the trainer never has it, and nothing upstream hashes or opens the test file (the forge and the trainer check it by name). A second evaluation on the same campaign (another run, a re-run after a fix) requires `--again "<reason>"`: `exposures` increments, the reason goes into `history`, and the layer, the notebook and the summary all say *the test has been seen n times* — the multiple-look penalty is not computed away, it is disclosed. **A look in an earlier campaign counts too.** A campaign `/vega-train --after-eval` started is a new directory with no seal of its own, and its `campaign.json.after_eval` (run-contract §1) records the looks the earlier campaign took at the same test part. `evaluate.py` reads it before the seal: the record must reconcile with the previous campaign's own `test_seal.json` (found as written, beside this campaign, or under the work dir; its `exposures` equal to `after_eval.exposures`), else the evaluation is refused with `ERROR:` and no seal written; and this campaign's first look is a **further** exposure, held to the further-exposure rules of §2 (no `--threshold <value>`, no `--slices`, no baseline set other than the one the previous campaign's evaluation measured, narrower or wider). The seal it writes counts every look — `exposures` is `after_eval.exposures + 1`, and the seal carries the `after_eval` record — so the layer, the notebook, the summary and the bundle disclose the total without any reader adding it up. An evaluation is also refused when the selected run's `checkpoint_digest` in `experiments.json` does not match `checkpoints/best.pt`, or when the test part's digest does not match the shaper's manifest (a changed test file is a new chain, not a new number).

## 2. The protocol (`scripts/evaluate.py`)

`python3 scripts/evaluate.py --campaign <dir> --run <id> [--again "<reason>"] [--threshold valid-optimum|0.5|<value>] [--slices …] [--baselines …] [--n-boot 1000] [--boot-seed 7] [--unattended]` first checks, **before writing the seal**, that the baseline set is at least the required one (§6), that every user slice gives a value, names a feature the slices read, and has a literal the column's dtype can hold (the dtype the shaper's manifest records in `output_schema`, else the train part's — no test row is read to decide it), and that the analysis layer's keys it will read exist where the analysis contract puts them (**the paths are the contract's, never guessed**: the importance protocol and ranking at `modules.importance.evidence.models[]` and `.permutation_importance[].feature`, the drifted columns at `modules.drift.evidence.columns[].column` with `drifted: true`, the segments at `modules.segments.evidence` (`profiles[]`, and `assignment` to cut them); a module that `ran` but lacks the key the evaluator needs is `ERROR: analysis layer key missing — <path>`, **never a silent skip** — a robustness check skipped on a false "no importance / no drift" at exposure 1 cannot be recovered without a second exposure) and — when `test_seal.json` already exists, or `campaign.json.after_eval` records the looks an earlier campaign took (§1) — that no `--threshold <value>` and no `--slices` were given and that `--baselines` is the previous exposure's set, neither narrower nor wider — this campaign's last evaluation, or the previous campaign's (on a further exposure the threshold is `valid-optimum` or `0.5` — and the same of the two the last look used, read from its `threshold.json`, since switching between them is choosing the threshold knowing the answer; after a look under a user value, which cannot be repeated, it is `valid-optimum`, the stage's default, never a mode picked after the look —, the slices are the chain's and the baselines are the ones already seen — a baseline dropped or added after a look changes the comparison knowing the answer —, because anything else is a choice made after a look); that every named baseline is one §4 defines; that the emitted package can be driven (a `v2.3` blueprint map with an `Evaluator` role, opened by `vega_core.PackageAdapters.load`); and that a `--threshold <value>` is a number the reading can use (a probability, in `[0, 1]`, for a binary or multilabel task); a violation is `ERROR:` with no seal written. Then it writes `eval/<run-id>/`:

- `predictions.test.parquet` — the layout `vega/predictions-layout@1`, the file every later number is computed from: `row_id` (the anchor row's raw position for a window, the node's for a node-level graph, the row's for a row sample — the raw input file's position, carried by the shaper's split indices — and the `graph_id` value at graph level, where a `graph_id` column repeats it); the truth as `y`, or `y_0 … y_{d-1}` when it has a dimension (a multilabel row, a forecast horizon, a reconstruction's numeric input; no truth column for an unlabelled part); the network's **raw head**, every `head_out` column, as `score` (one output) or `score_0 … score_{k-1}`, for every reading — what the package's `TaskReadout` reads, never a derived score stored in its place; `row_score`, the readout's per-row score, for the reconstruction and anomaly readings (numeric MSE plus the mean nominal cross-entropy, or ‖f(x) − c‖² for svdd); `prediction` (0/1) for a threshold reading — σ(score) ≥ threshold for a binary head, the probability of `task.classes[1]`, and `row_score` ≥ threshold for an anomaly score, absent when no threshold applies; and each fitted baseline's score per the score contract — and `campaign-baseline`'s, when R0 was predicted through the seal (§4) — as `score_<baseline>`, or `score_<baseline>_<k>` for a matrix score (every class of a multiclass task), so every metric can be recomputed from the record. Its parquet key-value metadata names `vega.row_id_kind` (`raw_position` | `graph_id`), `vega.truth_shape` and `vega.score_shape` (the per-sample shapes stored, `[]`, `[k]` or `null`), `vega.task_effective` (the kind the scores are read as: a `sequence-*` task's base) and `vega.predictions_layout`;
- `unscored.json` — the samples that got no prediction and why (`{count, reasons: {insufficient_context, horizon_beyond_part}, rows: [{row_id, reason}]}`): windows without enough context, forecast anchors whose horizon runs past the part; none is given a fabricated prediction;
- `metrics.json` — per model (the network and each baseline): every metric of the task's row in §3, point estimate, bootstrap CI (percentile, `n_boot` resamples of the test rows at `boot_seed`, the same resamples for every model so the *difference* has a CI too; the interval level is recorded as `ci_level`, `0.95`), and for the network vs each baseline the paired difference with its CI and whether it excludes 0; `predictions_layout` names the layout above, `task_effective` the kind the scores were read as, `options` what the metrics read beyond the scores (`season`, and `mase_scale` — the train target's seasonal scale — for a forecast), `n_unscored` the count of `unscored.json`, `class_support` (a reading with classes) the sealed test part's count of each class by name (a multilabel head: each label's positives) — what each per-class reading rests on, `upstream` the selected run's **valid** metrics as the ledger recorded them (`{valid: {<metric>: {value, _upstream: true}}}` — carried, never re-measured, so without an interval), `gates` the data-dependent metric gates decided on the train part (`{metric: {applies, share, rule, part, why}}`, below), and `graph` the exposure record of a graph sample (the seal's, plus — under `transductive` — the spec's declared `exposure`, `{kind, rows, source}`); its `verdict` object is the **machine verdict** the evaluator writes — `{ earned, strongest_baseline, diff, ci, beaten_by_baseline }`, where `strongest_baseline` is the fitted baseline with the best test primary in the direction of `metrics.selection.mode`, `earned` is true only when the paired difference against it excludes 0 in the mode's direction and `beaten_by_baseline` only when it excludes 0 the other way; on a primary that lives on each model's own score scale (§5: an unlabelled anomaly task's `anomaly_score_mean`) the verdict is **not assessable** — `{ earned: null, strongest_baseline: null, diff: null, ci: [], beaten_by_baseline: null, reason }` — and `differences` is empty — the apply script splices it and refuses a layer whose `verdict.earned` disagrees with its own `ci` (§6);
- `curves/` — ROC, PR, calibration (reliability with ECE bins), confusion matrix at the decision threshold, residual plots (regression), score distributions per class, as SVG and as the underlying points in JSON;
- `threshold.json` — `{applies, value, scale, per_label, source, why, metrics_at_threshold}`: for the threshold tasks, the decision threshold, the scale it lives on (`probability` for a `binary` or `multilabel` reading, whose scores are logits read through σ unconditionally; `score` for an `anomaly` reading, on the anomaly score's own scale), its source (`valid-optimum` — the default: the threshold on the **valid** part that maximises `f1` for `binary`, `f1` per label for `multilabel` — the per-label chooser, `per_label` keyed by class name, with `value` the one threshold that maximises `f1_micro`, which a label valid cannot place takes —, and the valid quantile at the expected anomaly rate for `anomaly`, its `f1` optimum on the score's scale when no rate is known and valid is labelled; `vega:default` 0.5 as the alternative; or `user:<turn>` on a first exposure only), and the metrics at that threshold (`metrics_at_threshold`: the network's threshold-dependent **test** metrics, the same estimates `metrics.json` holds, each with its bootstrap CI — never a bare number). Each fitted baseline gets **its own** threshold, chosen on its own valid scores by the same rule and request as the network's (valid-optimum, `vega:default` 0.5 or the user's first-exposure value; for `anomaly`, the valid quantile at the same expected rate on its own score's scale) and recorded in its `baselines.json` row as `decision_threshold` (`at`, `per_label`, `scale`, `source`, `why`): its threshold-dependent metrics, its primary and its paired difference are read at it, and the notebook recomputes them at it — a threshold chosen for one model would handicap every other read at it. The campaign's R0 row, a network run predicted through the seal and never the verdict's, is read at the network's; `applies` is false, and `value` null, for a reading that decides by argmax, by cumulative count or not at all, and for an anomaly task with neither a label nor `task.anomaly_rate` (nothing says where normal ends: the reading answers the score);
- `slices.json` — per slice, the primary and secondary metrics with CIs and `n`; slices come from the chain: the analysis's segments (`analysis:modules/segments` — one slice `segment:<id>` per k-means segment, each test row placed by the analysis's own rule, `modules.segments.evidence.assignment`: the nearest of its `centroids` to `(x − center) / scale` over its `features`, data-lens analysis-contract §1; the rule reads **raw** columns, so a row sample's raw test rows are read after the seal, as part of the one look, at the raw positions the shaper's `fitted.json.__split_raw__.test` records in the test part's order; a row missing a feature belongs to no segment and a `WARN:` counts them; the slice's note says what the segment is in the analysis's terms), the values of each nominal feature with ≥ 30 test rows, the drift-suspected columns (`analysis:modules/drift` — read at the analysis contract's actual path, `modules.drift.evidence.columns[]` where `drifted` is true) split at their train median, the time order (first/last quartile) when `context.time` exists; a slice the user names (`--slices col=value`) with `user:` source — given on the **first** exposure only (on a further one `--slices` is refused before the seal), its literal **coerced to the column's dtype** (`1` matches a float column holding `1.0`, `"1"` a string column; the dtype is the shaper's `output_schema`'s, else the train part's, so the coercion reads no test row), and a slice with no value, on a column that is not one of the features, or with a literal the dtype cannot hold **refused before the seal is written**, because slices are first-exposure only and a lost slice is lost for good. Whether a slice has rows is a fact about the test part, which is read only after the seal: a declared slice is measured with the chain's slices in the one look, and one that matches fewer than five test rows is recorded as a `WARN:` saying what the column holds — never silently dropped, and never re-declared on a second look; and a slice the chain named that this look cannot cut is a record, `slices.json.not_cut[]` (`{source, why}`, spliced into the layer and said on its slices surface) beside a `WARN:` — for the segments: the module did not run, it chose no k, it recorded profiles without the assignment rule (a layer published before the rule was recorded: a profile describes a segment and cannot place a row in one), the raw test rows cannot be read where the shaper's records put them, the sample is not one raw row (a window, a graph), or a segment holds fewer than five test rows — never a silent omission;
- `baselines.json` — each fitted baseline's definition, its training protocol, its own `decision_threshold` for a threshold task (above: chosen on its valid scores, never the test part's), and its valid primary with a bootstrap CI on the valid part (a number this stage computes travels with an interval like any other); `campaign-baseline`, when present, is a row marked `fitted: false` whose valid value is the ledger's (`_upstream: true`, its `valid` the one entry of the row the apply script's CI rule exempts) and whose **test** metric is measured through the seal (`predicted: true`, §4) with a bootstrap CI like any other, and a paired difference in `metrics.json.differences` — or, when R0 cannot be predicted (no R0 run or checkpoint, a checkpoint that does not hash to the ledger's digest, a sample that scores other rows), `predicted: false`, `test: null` and `why`, with a `WARN:`; the `lens` row records the protocol it re-fitted — `family`, `delegate` (`tree` or `linear`), `hyper_parameters` (`{applied, not_carried}`, each one not carried with why) and `protocol_source`;
- `robustness.json` — every entry a metric with its bootstrap CI like any other: when the analysis measured drift, the primary on the drifted vs stable slices; when `context.time` exists, the primary by time quartile; when the analysis's `importance` module ran, the change in the primary when each of its top-3 *numeric* features is perturbed by one train standard deviation (a cheap check that the network uses what the analysis said matters — the ranked columns are matched to the shaped test frame by name, the shift is one standard deviation of the shaped train column (shaped units), and a ranked column the shaping renamed, dropped or encoded, or a nominal one, is recorded as skipped with that reason; nominal features, windowed inputs and graph inputs are skipped and said so); without an analysis layer, `robustness.json` holds only what the seal and the time context allow and says which entries were skipped. The slices of a window sample read each window's anchor row, those of a node-level graph each node's own row; a graph-level sample has no one row, and only the time order slices it.

The evaluator is the emitted package's `Evaluator` adapter (`code-contract.md` §2), driven by this skill's `evaluate.py` through `vega_core.PackageAdapters.load` (the adapters by blueprint-map role; a package of an older generation is refused before the seal): `Evaluator.scored(spec, part, model)` is the one scoring path for the network and every baseline, and `Evaluator.heads` gives the raw head the predictions store; every metric is the emitted `metrics.metric(name, y_true, y_score, options, task)`, with the task's effective kind and one `MetricOptions` value, and the Evaluator's own `measure` calls the same `metrics.py` (`metrics.for_task`), so there is one metric implementation with two call sites, never a second computation; the threshold chooser (`scripts/threshold_choice.py`) reads every `f1` and `f1_micro` it maximises through the same `metrics.metric` at each candidate threshold, and computes none itself. Each baseline is a `Model` implementation in the files the blueprint map gives the role `baseline` (`baselines.py`, `baselines_extra.py`, emitted by the forge's backend template) so it is loaded, trained and predicted through the same ports as the network: fitted on the train part's design matrix in its own view (`design_of`, §4). The evaluator never trains the network; it loads `checkpoints/best.pt` of the selected run through the `ModelStore`. It trains the **baselines** — that is the one place it fits anything — on the train part with the valid part for their own early stopping or selection, under the spec's `seed` (the bootstrap has its own `boot_seed`, default the same value), on exactly the shaped features the network saw. The primary metric is the spec's `metrics.primary` (the forge chose it on the train part's class balance); the metric gates that depend on the data (`mape` when |y| > 0.1 for 99 % of rows — `scripts/catalog.json`'s `metric_gates`) are decided on the train part's targets, never the test part's, and recorded in `metrics.json.gates`: a metric its gate withholds is in every model's record as `value: null` with the reason in its `note` — never a number — and a `WARN:` says so; one that is the spec's primary is still reported with its value and interval in every model's record (the verdict reads them), with a `WARN:` naming the gate it fails — the one exception to `value: null`, and the apply check's refusal of a withheld metric that carries a value exempts it (`apply_evaluation_layer.gate_problems`).

## 3. Metric catalog per task

`scripts/catalog.json` is the machine copy of this section and §4, which `evaluate.py` and the apply script read; `scripts/tests/test_catalog_sync.py` fails when the two diverge, and the stage ships only with it passing.

| task | primary | secondary (all reported) | threshold-dependent | curves |
|---|---|---|---|---|
| `binary` | `pr_auc` when imbalanced (train minority share < 0.3), else `roc_auc` — as the spec's `metrics.primary` says | `roc_auc` / `pr_auc`, `log_loss`, `brier`, `ece`, `accuracy`, `balanced_accuracy`, `precision`, `recall`, `f1`, `mcc`, `specificity` | precision, recall, f1, mcc, accuracy, confusion at `threshold.json` | ROC, PR, reliability, confusion, score histograms |
| `multiclass` | `f1_macro` | `accuracy`, `balanced_accuracy`, `log_loss`, `f1_micro`, `f1_weighted`, `mcc` (multiclass Matthews correlation — the one number comparable with papers that rebalance their test set), per-class precision/recall/f1, `top_k` (k = 3, or the number of classes when there are fewer), `ece`; nothing on a collapsed binary task (a negative class against the rest) is computed here — this stage reports only the metrics the backend's `metrics.py` implements | per-class at argmax | confusion (normalised), one-vs-rest PR per class, reliability |
| `multilabel` | `f1_micro` | `f1_macro`, `pr_auc` per label and `pr_auc_macro`, `hamming`, `subset_accuracy` | per label, at `threshold.json` | per-label PR |
| `regression` | `rmse` | `mae`, `r2`, `mape` (when \|y\| > 0.1 for 99 % of train rows; withheld otherwise, §2), `median_ae`, residual quantiles (5, 25, 50, 75, 95), `spearman` | — | predicted vs actual, residuals vs predicted, residual histogram, QQ |
| `ordinal` | `mae_ordinal` | `accuracy`, `qwk`, `spearman` | at argmax of cumulative | confusion |
| `unsupervised` (reconstruction) | `reconstruction_error` (mean per row) | per-feature error, error quantiles, `r2` of reconstruction per feature | — | error histogram, per-feature error bars |
| `anomaly` | `pr_auc` on the score when a label exists, else `anomaly_score_mean` (the mean per-row anomaly score, mode min) | `roc_auc`, `precision_at_k` (k = expected anomaly rate × rows; the rate is the train part's positive share when a label exists, else the spec's `task.anomaly_rate` the forge asked for), `recall_at_k`, `f1` at the valid-chosen threshold, `anomaly_score_mean` — the ones that read a label (`roc_auc`, `precision_at_k`, `recall_at_k`, `f1`) only when the test part carries one; an unlabelled part reports `anomaly_score_mean` and says the others need a label | at `threshold.json` (valid quantile) | PR, score histogram by class |
| `sequence-*` / `forecast` | as the base task; `forecast`: `mase` | the base task's row; `forecast` adds `smape`, `rmse`, `mae` per horizon step, coverage when quantile loss | as the base task — `sequence-classification` decides at `threshold.json`, `sequence-regression` and `forecast` decide nothing | per-horizon error, a few series with predictions |

Every metric is computed by the emitted `metrics.py` — the backend's one implementation, which covers every metric named in this table and in the family catalog's task table (its `coverage.json` lists them) and is the same file the trainer used on valid — so a valid number and a test number are the same code, and the notebook calls the same functions on the stored predictions. Two numbers are *upstream* and carry no new CI: the selected run's `valid` metrics from the ledger, and `campaign-baseline`'s ledger value; everything a baseline is fitted for here carries a CI.

## 4. Baselines — what the network must beat

| baseline | definition | why it is in |
|---|---|---|
| `trivial` | majority class / class prior (classification), mean (regression), mean reconstruction (unsupervised) | the floor every metric is read against; a network below it is broken |
| `linear` | logistic regression / ridge on the shaped features (the shaper already scaled and encoded them), L2 chosen on valid; for `unsupervised` / `anomaly`: PCA reconstruction at the network's bottleneck size (the `pca-floor`) | the linear floor: what the network's non-linearity buys |
| `tree` | gradient-boosted trees (`lightgbm` or scikit-learn `HistGradientBoosting`), depth and rounds chosen on valid with early stopping; for `anomaly` without a label: isolation forest; for `unsupervised`: not defined, and the row says so | the honest tabular contender; on most tabular sets it is the number to beat, and the blueprint's posture may have bet on it |
| `lens` | the algorithm and protocol `/data-lens`'s `importance` module recorded (its model family and hyper-parameters), **re-fitted here on the shaped features** — the analysis fitted it on pre-shaping columns, so only the protocol carries over: its family picks `tree` (a tree, forest or boosting) or else `linear` (any other family, its row's `family` naming what it stands in for), fitted as that baseline is, and its recorded `hyper_parameters` (read where the analysis contract §1 puts them, at `modules.importance.evidence.models[]`: the entry whose `name` the `permutation_importance[].model` names — the model the analysis reported importances for, its best cross-validated one, so without that list the best `cv_score` is the same entry; a layer written before that form, with the protocol at the module's top level (`modules.importance.family` and `modules.importance.hyper_parameters`), is read there; the row's `protocol_source` names the path read) are set on that estimator; one the estimator does not take, and the seed (the baselines fit under the spec's), is named in the row as not carried. Those hyper-parameters are settings, not a selection: `/data-lens`'s learnability protocol fits fixed models under cross-validation — its analysis contract's `importance` row states the two models run at fixed hyper-parameters, with no search over them — so no hyper-parameter in the record was chosen on any rows; here they are carried as recorded, never re-selected, and `lens` is fitted on the train part with valid for its early stopping like every baseline — nothing about it is tuned on valid or test | continuity with the analysis's learnability estimate, on the features the network saw |
| `campaign-baseline` | the network's own `R0` run — its stored `best.pt`, predicted through the seal on the rows the network was scored on (R0's own emitted code, in a child process of the one look), with a test CI and a paired difference; a comparison row, not a fitted baseline, and labelled so — it is never the verdict's strongest fitted baseline | what the ladder and the search bought |
| `naive` | persistence: the last observed target, repeated over the horizon (a sequence regression repeats the row before the anchor); in the default set when the task is `forecast` or `sequence-regression` | the forecast floor: a network that cannot beat yesterday's value has learned nothing about the series |
| `seasonal-naive` | seasonal persistence: horizon step h repeats the target s·⌈h/s⌉ rows before it (s = `sample.season`); in the default set when the task is `forecast` or `sequence-regression` and the sample names a season | the floor of a seasonal series: a network that cannot beat last season's value has learned only the season |
| `graph-linear` | logistic / ridge on `[x ‖ mean of the in-neighbours' x]` over the scored view's edges — one fixed propagation (SGC-style); in the default set when the sample is a node-level graph | at node level `linear` and `tree` are structure-blind (they read the node's own features, and are named so): this is the honest contender for what learned message passing bought |

An anomaly task, labelled or not, is read against the same baselines as its reconstruction family: `trivial`'s mean reconstruction, `linear`'s and `tree`'s anomaly variants. The default set is the first five rows, plus the rows whose definition says when the task or the sample adds them (the catalog's `default_when`). The shape changes what `trivial`, `linear` and `tree` read, never what they are: a window is flattened (`L·F′ + L·C` columns), a node-level target is read by its own features, a graph by its nodes' `[mean | max | sum]` (the catalog's `by_shape`). Each fitted baseline's valid metric (in `baselines.json`, with its CI) is reported beside its test metric (in `metrics.json`, with its CI), so a baseline that was tuned on valid and collapsed on test is visible; `campaign-baseline`'s valid number is the ledger's (`_upstream`) and its test number is predicted through the seal (§4), or `null` with the reason when R0 cannot be predicted. A baseline the environment cannot fit (`lightgbm` absent → scikit-learn's HGB; both absent → `WARN:` and the row says `not fitted`) is never silently dropped.

## 5. The verdict

The verdict is a reading with a fixed form: **the network's primary metric with its CI; the paired difference against the strongest fitted baseline (named) and against `linear` with their CIs and whether each excludes 0; whether the network earned its cost** (a network that does not beat the strongest fitted baseline by a difference whose CI excludes 0 has not — the verdict says so plainly and names what the user gets instead: calibration, a smoother score, a serving property, or nothing); the calibration reading (ECE and the reliability curve: over-confident, under-confident, well calibrated; what any class weighting did to it (a binary `pos_weight`, a multiclass task's class weights, an anomaly task's positive weighting) — for the tasks whose row defines `ece` (the class and anomaly tasks); for the value, ordinal, reconstruction and forecast tasks the calibration reading is the residual or coverage reading their curves give, said in those terms); the slices where the network is worst, with `n` (a slice below the trivial baseline is named); the robustness readings; and what the evaluation cannot say (one test part, one seed, `n` rows — the CI width is the honest limit).

**A verdict that is not assessable.** A paired difference is a finding only when both models' numbers are on one scale. On an **unlabelled anomaly task** they are not: the primary, `anomaly_score_mean` (§3), is each model's own anomaly score averaged over the test part — the network's reconstruction error (or its distance to the svdd centre), the `tree` row's isolation-forest score, the `linear` row's PCA reconstruction error — and with no label to rank them against, a difference between two of them compares their scales, not the models. There the machine verdict is **not assessable**: `earned` is `null` — neither earned nor not earned —, no baseline is named, no difference or interval is recorded, `beaten_by_baseline` is `null`, and `reason` says why; every model's metrics are still reported with their CIs (`metrics.json.models`, `baselines.json`), and **no paired difference is computed** (`differences` is empty). The verdict reading states the network's primary with its CI, says in words that the verdict is not assessable and why, and claims neither a win nor a loss; every later reader of the record (the layer's render, the notebook, the bundle, `/vega-show`) says *not assessable* and never shows it as a win or a loss. The words are this verdict's alone: a reading of a verdict read off its interval never calls it not assessable. A labelled anomaly task (primary `pr_auc`, a ranking of the label by each model's score, whatever the score's scale) keeps the ordinary verdict.

```json

  "schema": "vega/evaluation@1",

  "curves": { "roc": { "points": "…", "svg": "<svg…>" }, "pr": "…", "reliability": "…", "confusion": "…" },
  "notebook": { "path": "vega-runs/…/evaluate.ipynb", "executed": true, "digest": "sha256:…" },
  "markers": ["OK: …", "WARN: …"],
  "readings": { "verdict": "<§5, the fixed form>", "calibration": "<…>", "slices": "<…>", "robustness": "<…>", "limits": "<…>" }

```

Required: `schema`, `seal`, `run`, `verdict` (the machine form: `earned`, `strongest_baseline`, `diff`, `ci`, `beaten_by_baseline` — or the not-assessable form with `reason`, §5), `metrics` (the network and ≥ `trivial` + one of `linear` / `tree` — for `unsupervised`, `trivial` + `linear` — each with CIs), `threshold` for threshold tasks, `baselines`, `slices`, `robustness`, `notebook` (with `executed`; `false` accompanied by `WARN: notebook not executed` in `markers`), and all five readings (`verdict`, `calibration`, `slices`, `robustness`, `limits`). The authoring file (`evaluation-layer.json`) carries `from_eval`, consumed and not stored. `scripts/apply_evaluation_layer.py` validates this — refusing any metric in `metrics`, `slices`, `robustness`, `baselines` or `threshold.metrics_at_threshold` without a CI, an `_upstream` mark anywhere in the measured records (`metrics`, `baselines`, `slices`, `robustness`, `threshold.metrics_at_threshold`) but their two upstream numbers (`metrics.upstream`, a baseline row's `valid`: a test number is never upstream — the layer's `run` block, which only identifies the selected run and repeats its ledger valid number, is not a measured record), a metric `metrics.gates` withheld that a model, slice or check still publishes with a value (the spec's primary excepted, §2), a threshold whose source names the test part or a `user:` threshold at `exposures > 1`, a machine `verdict` whose `earned` does not follow from its own interval in the mode's direction (or whose `beaten_by_baseline` does not), an earned verdict naming no fitted baseline, a verdict on a primary that lives on each model's own scale (§5) that is not the not-assessable record (`earned` null, its `reason`, no baseline, difference, interval or `differences`), and a not-assessable verdict anywhere else, a `readings.verdict` that does not contain the `verdict` object's numbers (the point estimate, the difference against the strongest fitted baseline and — when `linear` was fitted and is not that baseline — against `linear`, with their bounds, as rounded in `metrics.json`) or whose *earned* statement contradicts `verdict.earned` (for a verdict that is not assessable: a reading that does not say *not assessable*, or that claims earned or not earned; for any other verdict: a reading that calls it *not assessable*), a `readings.slices` that does not name the worst slice with its `n`, and any number in a reading that does not appear in the spliced records at the same rounding — a retyped digit is refused; it writes the `notebook` record itself from `--notebook <path>` (notebook-contract.md §3) — and injects the shipped `assets/evaluation-render.js` + `assets/evaluation-layer.css` through `domain-forge/scripts/apply_layer.py`, and adds a `<noscript>` fallback (the metrics table with CIs, the baselines, the verdict).

The render mounts one tab, `data-layer="evaluation"`, labelled **Evaluation**: the seal strip (run, opened when, exposures), the metrics table (network and baselines, point and CI, the paired difference with its CI highlighted when it excludes 0), the curves (SVG, drawn from the points), the slices table sortable by primary metric with `n`, the robustness panel, the verdict and readings. It reads only `layer-evaluation-data`, idempotent, empty state when missing, ≤ 60 KB of JS, SVG only, keyboard-operable, `window.__evaluation = { metrics(), slices(), version }` for tests.

## 7. Naming, memory, hand-off

Output: `<input-stem>.eval.html` (`…shaped.vega.train.html` → `…shaped.vega.train.eval.html`); the evaluation in `vega-runs/<ts>/eval/<run-id>/` and `evaluate.ipynb` in `vega-runs/<ts>/`, the seal beside `campaign.json` (the campaign's tree, `run-contract.md` §1, names these as this stage's additions). Memory: § **Network stances** — one line per evaluation (`YYYY-MM-DD | <dataset> | eval H1-14 on test (exposure 1): pr_auc 0.71 [0.62, 0.79], vs tree +0.02 [−0.03, 0.07] — not earned`, or, on a verdict §5 defines as not assessable, `… — not assessable: <reason>` with every model's primary and no difference; the exposure number qualifies the verdict and is repeated here for that reason — the seal file is its truth, the ledger its chain state), plus a threshold or slice the user declared. Hand-off: `/vega-pack <out>` when the verdict justifies shipping (or the user says ship anyway — a stance), `/vega-train … --after-eval` for a new campaign (the summary says how many times the test has now been seen — the seal's `exposures`, which in an after-eval campaign counts the earlier campaign's looks too), `/dataset-shaper` or `/data-lens` when a slice or robustness reading points at the data rather than the network.

## 8. What proves the evaluator covers every cell

The evaluation's one scoring path is the one this contract names, and the backend coverage matrix (`vega-forge/scripts/tests/matrix/run_matrix.py --cells all`, report `vega/backend-matrix@1`) drives it on every cell of `vega-forge/scripts/catalog.json`'s admission table (`vega-forge/references/family-catalog.md` §7): under a `test_seal.json` as this stage writes one, the Evaluator's one scoring path (§2) scores the test part and lays it out as `vega/predictions-layout@1` — every value finite, the row ids the test part's (its rows, nodes, graphs, or window anchors with every other row counted unscored with its reason). An evaluator change ships only when that report is green (`summary.failed == []`) and its cell list equals the admission table (`admission.table: "equal"`); a task kind, shape or level this stage claims to evaluate and the matrix does not score is a coverage defect.
